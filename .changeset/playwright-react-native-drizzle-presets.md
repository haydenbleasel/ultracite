Add `playwright`, `react-native` and `drizzle` framework presets. `ultracite init` offers them, and pre-selects them when the project depends on `@playwright/test`, `react-native` or `drizzle-orm` (React Native also pre-selects React). The ESLint presets use each library's ESLint plugin, the Biome presets use the rules Biome 2.6 made stable, and the Oxlint presets add no plugin rules, because Oxlint has no plugin for these libraries.

- **Playwright:** `ultracite/eslint/playwright` turns on every rule in [`eslint-plugin-playwright`](https://github.com/mskelton/eslint-plugin-playwright) in test files, except `no-hooks`, `require-soft-assertions` and `require-tags`, which would report ordinary tests. `ultracite/biome/playwright` turns on Biome's Playwright rules, such as `noPlaywrightMissingAwait` and `noPlaywrightWaitForTimeout`, and the test rules the Jest and Vitest presets use, such as `noFocusedTests` and `useExpect`. It leaves out `useConsistentTestIt`, because Playwright has no `it()`. On every linter, a hook that only needs `testInfo`, as in `test.beforeEach(async ({}, testInfo) => ...)`, no longer trips core's empty-pattern rule.
- **React Native:** `ultracite/eslint/react-native` turns on the rules in [`eslint-plugin-react-native`](https://github.com/Intellicode/eslint-plugin-react-native) and Meta's [`@react-native/eslint-plugin`](https://www.npmjs.com/package/@react-native/eslint-plugin), such as `no-raw-text`, `no-unused-styles` and `no-deep-imports`. `eslint-plugin-react-native` hasn't been updated for ESLint 10, so the preset wraps it with [`@eslint/compat`](https://www.npmjs.com/package/@eslint/compat), which `init` installs too, and npm projects get a peer override for it. `ultracite/biome/react-native` turns on `noReactNativeRawText`, `noReactNativeLiteralColors`, `noReactNativeDeepImports` and `useReactNativePlatformComponents`. Both declare the `__DEV__` global.
- **Drizzle:** both presets turn on the rules that report a `delete()` or `update()` with no `.where()` ([`eslint-plugin-drizzle`](https://orm.drizzle.team/docs/eslint-plugin) and Biome's `noDrizzleDeleteWithoutWhere` and `noDrizzleUpdateWithoutWhere`), for objects named `db` or `tx`. Without a name, the ESLint rules report every `.delete()` call, `Map#delete` included, and the Biome rules report nothing.

These rules check their libraries' APIs, which is why they're in presets rather than in core. On Biome they would otherwise misfire: an explicit severity overrides Biome's dependency check, so `noReactNativeRawText` in core would report text inside any JSX element, including a `<div>`.
