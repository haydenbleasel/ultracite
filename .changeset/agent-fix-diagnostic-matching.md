"ultracite": patch
---

`ultracite fix --claude` and `--codex` now recognise an issue that's still reported after the agent's edit when a limit rule's message changed only by its count, when a message changed only by the line it points at, or when the same rule reports several times with the same message.

- A limit rule such as `max-lines-per-function`, `max-statements`, `max-params` or `complexity` puts the count in its message ("too many lines (88)"). A function the agent cut from 88 lines to 55 was counted as one issue fixed and one new issue, and the retry told the agent its edit had "resolved the issues it was given". It's now the same issue, still reported. Only the limit rules (the `max-*` and complexity rules, and Biome's `noExcessive*` and `useMax*`) are matched without their numbers, so a `no-magic-numbers` report for `100` isn't taken for the `42` the agent fixed. Other rules ignore only a line or column a message points at, or a count of repeats (`no-shadow`'s "declared in the upper scope on line 3", `sonarjs/no-duplicate-string`'s "duplicating this literal 3 times"), since an edit anywhere in the file changes those. A report whose message changed only by some other number, such as `import/no-cycle`'s "Dependency cycle via ./b:3", is still the same issue when it's where the edit left the original's line.
- Rules such as `typescript/no-explicit-any` give every report the same message. When an edit added new reports above the original ones, the retry called the agent's new ones "still reported" and pointed at the untouched originals as "new since the previous edit". Reports are now matched by the line of code they're on first, and then by where the edit left an original's line, between the nearest unchanged lines around it. A report there is the original, rewritten. An original whose surroundings are still there with no report among them counts as fixed, so a report the edit added elsewhere is new. Reports whose place can't be told, such as code the edit moved, or a limit rule like `max-lines`, which reports where its count runs out, are matched in file order as before.
