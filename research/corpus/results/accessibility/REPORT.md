# Accessibility lint rules in real React codebases: measurement report

The data behind the accessibility post, measured on 2026-10-15. Generated tables are in `tables.md`. The machine-readable results are:

- `inventory.json`, `rule-census.json` and `rule-census.md`
- `linters.json`: the calibration matrix with every message and help text, the template-language matrix, the crash case, what each fix pass does to each case, and ESLint and Biome on the corpus with every line where the linters disagree
- `disagreements.json`: the same comparison by JSX element, with what each disputed element is
- `markers.json`: suppression comments and each repo's own lint config lines
- `jsx-census.json`: what JSX-level rules can't see, and the two counterfactual lints
- `sample.json`, `classifications.json` and `barrier-match.json`
- `history.json`, `history-lint.json` and `history-verdicts.json`
- `decision-history.json`

The agent-experiment subjects are in `corpus/examples/accessibility/`. Everything is regenerated by `research/corpus/scripts/a11y-*.cjs` (see §12).

"Accessibility rule" here means a rule whose purpose is that people using a screen reader, a keyboard, voice control or reduced motion can perceive and operate the UI:

- `jsx-a11y/*` in Oxlint and in ESLint (eslint-plugin-jsx-a11y), and `astro/jsx-a11y/*`, its wrapper in eslint-plugin-astro
- Biome's `a11y` group
- `github/a11y-*` (eslint-plugin-github) and four sonarjs rules about tables and `<object>`
- `react/button-has-type` and `svelte/button-has-type` (Biome files the same check under a11y)
- the 102 react-doctor rules that react-doctor itself files under "Accessibility"
- `svelte/valid-compile`, which reports the Svelte compiler's `a11y_*` warnings

The catalogue is in `a11y-lib.cjs`.

## TL;DR

- **Corpus.** The topic needed more JSX than the shared corpus has, so it adds four React codebases (`scripts/repos-accessibility.json`): shadcn/ui's registry, Radix Primitives, React Aria Components and Supabase Studio. With Excalidraw, Next.js and tRPC from the shared corpus, that's 7 repos, 2,793 JSX files and 476,153 JSX lines.
  - Supabase Studio is 65% of the lines, so pooled numbers are also given without it (165,427 lines).
  - `repos.json` and every earlier topic's numbers are unchanged.

- **What Ultracite turns on.**
  - **Oxlint:** the react preset turns on all 35 non-nursery `jsx-a11y` rules but `no-autofocus`, plus `react/button-has-type`, with no options. Core has no accessibility rule. The opt-in js-plugins preset adds 16: github 5, sonarjs 4 and react-doctor 7. The vue, svelte, astro and angular presets add none, and Oxlint never reads a template: it lints only the `<script>` blocks of `.vue`, `.svelte` and `.astro` files, and not `.html` at all.
  - **ESLint** turns on 65 rules for `.tsx` and `.jsx`: 35 `jsx-a11y` (all but `no-autofocus`), `react/button-has-type`, 20 react-doctor, and core's 5 github and 4 sonarjs rules. `label-has-associated-control` gets `controlComponents`, `labelComponents` and `depth: 3`.
    - JSX in a `.js` file gets only the 9 core rules. The react block is scoped to `**/*.{jsx,tsx}`.
    - The Astro preset turns on all 36 `astro/jsx-a11y/*` rules, `no-autofocus` included, with no label options.
    - The Svelte preset gets the compiler's a11y warnings through `svelte/valid-compile`.
    - Vue and Angular templates get nothing: no eslint-plugin-vuejs-accessibility, no `@angular-eslint/template`.
  - **Biome core** turns on 37 of the 38 rules in the a11y group (`noAutofocus` is off). They run on JS and TS files with JSX, and on `.html` files with core alone. On `.vue`, `.svelte` and `.astro` files they run only with the framework preset, which turns on `html.experimentalFullSupportEnabled`.
  - **What the template linters catch.** Of 10 template barriers, Biome finds 9 in every language. It misses `autofocus`, and in Angular templates it doesn't read `(click)`.
  - **`no-autofocus` is off in every React preset but on in Astro and Svelte.** No reason was ever recorded for turning it off (§4.1).

- **How often the rules fire** (raw, per 10,000 JSX lines):
  - Oxlint's default presets: 521 diagnostics (10.9)
  - with js-plugins: 813 (17.1)
  - ESLint: 873 (18.3)
  - Biome: 628 (13.2)

  Without Supabase the rates are 14.3, 22.2, 23.7 and 18.6. By repo, Oxlint's default rate runs from 0 (tRPC) and 7.5 (Radix) to 37.8 (shadcn).

  - **The top rules are about roles and titles, not barriers:** `prefer-tag-over-role` 171, `github/a11y-no-title-attribute` 145, `no-static-element-interactions` 75, `github/a11y-svg-has-accessible-name` 74 and `click-events-have-key-events` 70.
  - **22 of the 52 focus rules never fire,** among them `aria-props`, `aria-role`, `aria-proptypes`, `tabindex-no-positive`, `iframe-has-title` and every sonarjs table rule.

- **Maintainers almost never suppress these rules.**
  - In all files of the 7 repos, 4 comments name an accessibility rule: 3 `oxlint-disable` comments in React Aria, each with a reason, and 1 `eslint-disable-next-line` in Supabase without one. Both raters judged all 4 justified.
  - Raw and reported counts differ by 4 diagnostics.
  - There is no `biome-ignore` comment for an a11y rule.

- **The three linters' "same" rules disagree by design.** Comparing them by JSX element (`disagreements.json`):
  - **`prefer-tag-over-role`:** Oxlint and ESLint flag 112 elements that Biome's `useSemanticElements` doesn't. Their roles are `status` 45, `combobox` 17, `row` 8, `img` 7 and `dialog` 7, and 42 of the elements are components.
  - **`noNoninteractiveElementInteractions`:** Biome alone flags 87 divs and spans, which its own `noStaticElementInteractions` already covers.
  - **`control-has-associated-label`:** ESLint alone flags 36 elements (29 inputs, 4 textareas). Oxlint's default ignores inputs and jsx-a11y's doesn't, so ESLint flags inputs that are already labelled. In calibration that includes the right fix itself.
  - **`label-has-associated-control`:** ESLint alone flags 17 custom `<Label>`s (its `labelComponents` option), and Oxlint alone flags 4 labels nested deeper than its default depth of 2.
  - **`useFocusableInteractive`:** Biome alone flags 33 composite-widget children (`gridcell`, `row`, `button` with roving focus).
  - **SVG names:** Biome alone flags 21 `<svg {...props}>`, where the github rule gives up because of the spread.
  - **Click handlers:** `click-events-have-key-events` agrees on all 70.

- **What JSX-level rules can't see** (`jsx-census.json`):
  - **Custom components:** 64% of the 45,570 JSX elements are custom components, which no `jsx-a11y` rule reads. The share is 34% in Excalidraw, 67% in Supabase and 76% in Radix.
  - **onClick:** it's passed to custom components 1,743 times, and appears on a non-interactive DOM element only 85 times.
  - **Spreads:** 3.4% of DOM elements have a spread pooled, but 89% in Radix and 77% in React Aria, where the role, tabIndex and key handlers arrive that way.
  - **Dynamic values:** 44% of `aria-label`s and 35% of `alt`s on DOM elements are dynamic, and calibration shows the rules accept any expression, `alt={src}` included.
  - **Components passed accessibility props:** `aria-label` goes to components 431 times against 130 times to DOM elements, and `alt` 64 against 51.
  - **What the components render:** of 3,168 button-like component usages, 61% resolve to a `<button>` in the same repo, mostly `asChild ? Slot : "button"`. 36% are third-party (Radix), which a single-repo check can't see into.
  - **Telling the rules what each component renders** (`settings["jsx-a11y"].components`, 1,832 names) adds 798 Oxlint diagnostics to a baseline of 516. In the hand sample of those, 23 of 30 are false positives and 4 are real barriers, among them unnamed icon-only `Button`s.
  - **Blanking every spread** on DOM elements (619) adds only 22 Oxlint diagnostics. The rules seldom bail on a spread; they just don't look inside it.

- **What the hits are** (72 sites sampled from 924, 12 per repo; a blind second rater agreed on 19 of 20, κ 0.88):
  - **52 are intentional or decorative** (72%, 64% weighted by repo): ARIA widget roles in Radix and React Aria, decorative SVGs and repeated `title`s.
  - **10 are real barriers** (14%, 20% weighted).
  - **10 are false positives.**
  - **Of the 10 real barriers, a rule names the actual problem in 5, plus 1 only by accident.**
    - Oxlint's default presets name it in 1, ESLint in 4 and Biome in 3.
    - In 3 the rule objects to something else, such as a working `role="checkbox"` whose real problem is a missing name.
    - `prefer-tag-over-role` fires at 29 sampled sites. 26 are intentional, and the other 3 are real barriers for a different reason.

- **Real fixes from history** (287 searches; 40 merged fixes in 6 repos, linted at each fix's parent commit):
  - **6 flagged:** a rule names the fixed barrier in 6 of the 40. All 6 are a `<div>` or `<span>` with onClick, a literal `tabIndex={10}`, or a focusable `aria-hidden` element. Oxlint and ESLint flag all 6, Biome 5.
  - **10 adjacent:** a rule fires on the lines, but about something else.
  - **24 untouched:** nothing fires.
  - **Name and label fixes:** none of the 13 is flagged; the labels were missing behind components, present but wrong, or plumbed through props.
  - **Other kinds:** none of the 4 focus-management, 3 contrast, 1 live-region or 1 reduced-motion fixes is flagged either.
  - **Library repos:** in Radix and React Aria, 1 of 14 is flagged.
  - **One maintainer suppression:** React Aria #5867's barrier sat on an element whose a11y rules had been suppressed, for a different reason.

- **Calibration and the evasion map** (129 cases: 87 barriers or correct code, 42 edits):
  - **What the linters go quiet on.** Of the 36 edits that don't fix their barrier (or fix it only partly), Oxlint's default presets go silent on 16, Biome on 16 and ESLint on 8.
  - **Silent in all three:**
    - `aria-hidden="true"` on a clickable div
    - `alt=""`, `alt={""}`, `alt={src}` or a filename on an informative image
    - `tabIndex={-1}` on an `aria-hidden` button
    - renaming a misspelled `aria-*` to `data-*`
  - **The no-op key handler can't be told apart from the real one.** `role="button" tabIndex={0} onKeyDown={() => {}}`, or a handler that only handles Escape, gets the same diagnostics as the correct ARIA button pattern: `prefer-tag-over-role` / `useSemanticElements` alone. Only ESLint's react-doctor `role-button-requires-complete-keyboard-activation` catches an Enter-only handler, and nothing catches a no-op.
  - **20 of the 87 base cases trip no rule in any linter.** Among them:
    - an icon-only button whose icon is a component
    - a `<select>` with no label
    - a custom `IconButton`
    - a button inside a link
    - dynamic `role`, `tabIndex` and `aria-hidden` values

- **What the fix pass does first** (what `ultracite fix` runs before an agent sees anything):
  - **`oxlint --fix`** removes `aria-hidden` from focusable elements, corrects `aria-labeledby` to `aria-labelledby`, and removes redundant roles.
  - **`oxlint --fix-dangerously`** (`ultracite fix --unsafe`) also adds `tabIndex={0}` to a `<div role="button" onClick>` with no key handler. That makes a focusable control that Enter and Space don't operate. It also writes `/* empty */` into a no-op `onKeyDown`.
  - **`biome check --write --unsafe`:**
    - deletes a misspelled `aria-labeledby` instead of correcting it
    - turns `<marquee>News</marquee>` into `News</marquee>`, which no longer parses
    - never terminates on `<div aria-activedescendant>`: `useAriaActivedescendantWithTabindex` adds `tabIndex="0"` and `noNoninteractiveTabindex` removes it.

    These are upstream Biome 2.5.15 bugs, and `ultracite fix --unsafe` would hang on that one line.
  - **ESLint crashes on one Supabase Studio file.** eslint-plugin-jsx-a11y 6.10.2's `prefer-tag-over-role` throws on a component with an object-valued `role` prop, which aborts the whole run (jsx-eslint/eslint-plugin-jsx-a11y#1102, open).

- **Agent-experiment subjects** (§10): both are real Excalidraw components (MIT) with a behaviour oracle and 20 hand-made variants.
  - **A, `Stats/Collapsible`:** a `<div onClick>` section header. Its tempting fixes (a no-op key handler, `role` plus `tabIndex`, `aria-hidden`, a spread) all clear Oxlint's `click-events-have-key-events` and leave the barrier.
  - **B, `ColorPicker/TopPicks`:** swatch buttons named only by a hex `title`. `aria-label={color}` silences Oxlint's `control-has-associated-label` and keeps the hex name. The sibling `PickerColorList` already names its swatches "Red — w".

## 3. Method

### 3.1 Inventory (`a11y-inventory.cjs`)

- **Oxlint:** every preset in `config/oxlint`. Category, fix kind and type-awareness come from `oxlint --rules`.
- **ESLint:** `calculateConfigForFile` on each file type a preset covers:
  - core + react on `.tsx`, `.jsx` and `.js`
  - core + astro on `.astro`, core + vue on `.vue`, core + svelte on `.svelte`
  - core + angular on `.ts`, and core on `.html`
  - core + next, solid and qwik on `.tsx`
- **Biome:** core's a11y group and each framework preset's overrides and `html` settings, plus `biome explain` for each rule's fix kind, options and the languages of its documented examples.
- **What actually runs** is measured by calibration (§3.5), not read from the configs.
- **react-doctor** files each rule under a category in its registry (`dist/core.js`). Its 102 "Accessibility" rules count here.

### 3.2 Census (`a11y-census.cjs` → `rule-census.cjs --files jsx`)

- **What ran:** core + react + js-plugins over the JSX files of the 7 repos, both modes, focused on the 52 accessibility rules those presets enable.
- **Raw mode** neutralises `eslint-` and `oxlint-disable` comments.
- **Line counts** are JSX lines.

### 3.3 Three linters on the corpus (`a11y-linters.cjs --corpus`, `a11y-disagreements.cjs`)

- **What ran:**
  - ESLint (core + react, a11y rules) on the census's raw mirror and on the original files, with inline config honoured.
  - Biome (core's a11y rules) on a mirror with `biome-ignore` neutralised as well, and on the originals.
- **Concepts:** the 38 shared concepts in `a11y-lib.cjs` `CONCEPTS` line the rules up.
- **Comparison:** each report is first compared by line. Then it's mapped to the innermost JSX element whose opening tag contains it, because ESLint reports at the element and Oxlint and Biome often at the attribute. The elements the linters disagree on are described: tag, kind, literal role, spread, `aria-hidden`, `aria-label`, `title`.
- **The ESLint runner survives rule crashes.** A chunk that throws is linted file by file, and a file that throws is linted again without the rule that threw.

### 3.4 What JSX rules can't see (`a11y-jsx-census.cjs --lint`)

The measurement is syntax only, plus module resolution inside each clone (TypeScript's, then workspace package names; tsconfig `paths`, with Studio's `baseUrl` supplied because its base tsconfig isn't in the sparse clone).

- **Elements:**
  - A lowercase tag is a DOM element.
  - `x.tag` with a lowercase DOM tag is a factory: `motion.div`, `Primitive.button`.
  - Anything else is a custom component.
- **Props:**
  - Every `alt`, `aria-*`, `role`, `tabIndex`, `htmlFor` on a `<label>`, and `id` on a form control on a DOM element is classified as literal or dynamic (by expression kind).
  - Spreads are counted, with what they spread.
  - The same props passed to components are counted too.
- **Handlers:** onClick and jsx-a11y's other handlers on non-interactive DOM elements, with whether `role`, `tabIndex` and a key handler are there literally, dynamically, or possibly in a spread.
- **Component families** are matched on the last segment of the name: button (`…Button`, `…Trigger`, `…Close`), link, label, textbox, choice, select, image, dialog.
  - Each usage is resolved to its definition through imports, re-exports, `export *`, `forwardRef`, `memo`, React Aria's `createHideableComponent`, and destructured namespace members.
  - The definition's returned root is classified:
    - a native element
    - polymorphic: a local `Comp` whose initializer has a DOM-tag string, such as `asChild ? Slot : "button"`
    - a factory
    - another component, followed up to depth 8
    - third-party
    - a provider, fragment or pass-through
    - unresolved
  - The DOM tags anywhere in the definition's own JSX are recorded, so a wrapper whose root is a `<div>` around the real `<input>` is visible.
- **Counterfactual lints:** each is compared with a baseline that has the same config (extends-only Oxlint, as the census runs it; ESLint core + react).
  - **mapping:** `settings["jsx-a11y"].components` set to every name that resolves to one DOM tag throughout its repo (1,832 names).
  - **spreads:** every spread on a DOM element blanked out to spaces, so positions don't move.

### 3.5 Calibration and the fix pass (`calibration/accessibility/`, `a11y-linters.cjs --calibration --autofix`)

- **`cases.tsx`** has 129 cases.
  - Each base case is a barrier or correct code. Each edit names its base case and says whether it fixes the barrier: `// E02 (C01, fixes: no): …`.
  - Whether an edit fixes the barrier was judged from the WAI-ARIA Authoring Practices button and link patterns and the HTML spec, not from any linter.
- **`templates/`** holds the same 10 barriers in `.js`, `.jsx`, `.html`, `.vue`, `.svelte`, `.astro` and an Angular `.html` template.
- **Edge cases:**
  - `crash.tsx` is the object-valued `role` prop.
  - `biome-fix-loop.tsx` and `biome-marquee-fix.tsx` are the two Biome fix bugs.
- **Configurations:**
  - Oxlint core + react, and with js-plugins
  - ESLint core + react, and core + astro, vue, svelte or angular for templates
  - Biome core, and core + the framework preset
- **What's recorded:** every message, Oxlint's help, ESLint's rule docs description, Biome's `biome explain` description (what Ultracite's agent handoff carries), and Biome's terminal notes.
- **`--autofix`** runs each fix pass on copies under the system temp directory and maps every changed hunk to its case:
  - `oxlint --fix` and `--fix-dangerously`
  - `eslint --fix`
  - `biome check --write` and `--write --unsafe`

  Biome's runs are diffed against a Biome-formatted copy, because `check` also formats. Every Biome write has a timeout, because of the loop.

### 3.6 Hand classification (`a11y-sample.cjs`)

- **Populations** (raw):
  - **hit:** every line any linter flags with an accessibility rule, merged by file and line (924 sites).
  - **hidden:** every line the mapping counterfactual adds (944).
  - **suppression:** every suppression comment naming an accessibility rule (4).
- **Sample:** seed 20261015, frozen in `sample.json`. Up to 12 hit sites per repo (72, none from tRPC), and 30 hidden sites in proportion to each repo's population, with at least 2 per repo.
- **Codebook** (in `sample.json`): real barrier, false positive, intentional or decorative, unclear; for suppressions, right, wrong or unclear. Raters also gave the cheap fix and the right fix.
- **Raters:**
  - Rater 1, a Claude subagent with read-only access to the clones, labelled all 106.
  - Rater 2, a separate Claude subagent, labelled a seeded blind subset: 20 hit sites, 20 hidden sites and all 4 suppressions.
  - Both are Claude models, so agreement measures how consistently the codebook applies.
- **`barrier-match.json`** (hand input) records, for each real barrier, whether a rule there names the barrier, names it by accident, partly, or not at all.

### 3.7 History (`history.json`, `a11y-history.cjs`, `history-verdicts.json`)

- **Search.** A Claude subagent searched the 7 upstream repos with `gh`: 287 searches, each logged with its hit count.
  - **Terms:** a11y, accessibility, screen reader, VoiceOver, aria, alt text, label, keyboard, focus, tabindex, role, contrast, WCAG, axe, accessible name, announce, live region and reduced motion.
  - **Title-only reruns** where PR templates saturate the bodies. React Spectrum has 3,484 body hits for "accessibility".
- **Selection.**
  - **Confirmed:** 40 merged fixes to a user-facing barrier in JSX/TSX code. The diff was read and the barrier's lines checked at the parent commit.
  - **Set aside:** 29 rejected candidates and 9 lint-driven cleanups.
  - **tRPC** has none: its `.tsx` files are hooks and providers.
- **Lint.** `a11y-history.cjs` downloads each file at the fix's parent commit and lints it with all three linters, raw and reported.
- **Verdicts.** I made the hand verdicts myself, from each barrier description and the rules on its lines. They're in `history-verdicts.json`, with one rater only.

### 3.8 Decision history (`decision-history.json`)

A Claude subagent ran `git log -S`/`-G` over every path the configs and the template have lived at. It also read the changelog and changesets, and searched `gh issue/pr list` on haydenbleasel/ultracite for 28 terms (§4.1).

### 3.9 Agent-experiment subjects (`a11y-examples.cjs`)

- **Checks:** each subject and each hand-made variant is linted with all three linters and type-checked (React's types from the Bun store), then run through a behaviour oracle.
- **How the oracle works:**
  - It transpiles the file and renders it with React 19's `renderToStaticMarkup`.
  - It wraps the JSX runtime and `createElement`, so every host element's props are recorded and tagged in the markup.
  - It calls handlers with synthetic click and key events.
  - It computes a reduced accessible name: `aria-labelledby`, `aria-label`, content outside `aria-hidden`, then `title`.
- **No DOM or axe-core is used**, and none is installed (§10).

## 4. Results

### 4.1 What Ultracite turns on

| Linter, preset | File type | Accessibility rules on | Off |

## 8. Findings worth stating carefully

- **Static rules catch markup, not behaviour.**
  - The rules that work are about a missing attribute on a DOM element: a clickable `<div>`, a positive `tabIndex`, an `aria-hidden` control, a label with no control. They found all 6 of the fixable barriers in the history sample.
  - The rest of that sample is out of reach, and so is most of what the hand sample calls a barrier:
    - names behind components or spreads
    - names that are present but wrong
    - focus management, contrast, runtime state
- **Most hits aren't barriers.** In this corpus 64% (weighted) are deliberate patterns. That's dominated by `prefer-tag-over-role` on correct ARIA widgets in exactly the libraries that shadcn and Supabase build on.
- **The rules can't tell a fix from an evasion.** A no-op key handler plus `role` and `tabIndex` is indistinguishable from the ARIA button pattern, and `aria-hidden="true"` silences everything. The behaviour oracle is what separates them.
- **"The same rule" isn't the same.**
  - ESLint and Oxlint run `control-has-associated-label` with different defaults, so one reports labelled inputs and the other never reports inputs.
  - Only ESLint knows about `<Label>` components.
  - Biome flags 87 divs a second time.
  - Per-linter counts aren't comparable without the element-level table.
- **The libraries built for accessibility look clean to lint, and their history is full of barriers lint couldn't see.** Radix and React Aria have the lowest hit rates and 13 of 14 un-flagged fixes, because their accessibility lives in hooks, contexts and spreads.

## 9. Caveats

- **Snapshot and mix.**
  - The repos are at their 2026-10-15 HEADs (2026-10-10 for the shared three).
  - Supabase Studio is 65% of the JSX lines, so pooled rates are given with and without it.
  - Five of the seven repos are libraries or frameworks.
  - shadcn is its new-york-v4 `ui` and `blocks` only, React Aria its component package only, and Studio its `components` and `pages`.
- **React only.** The Vue, Svelte, Astro and Angular results come from calibration templates, not from corpus code.
- **The classification is judgment.**
  - Claude raters used a codebook on 72 + 30 + 4 sites.
  - Several labels are judgment calls the raters flagged, mostly real barrier against intentional when the rule's reason is wrong but the element is broken.
  - For h005, rater 2 read Base UI's source from an unrelated local project outside the corpus (read-only); rater 1 marked the same item hedged.
  - The history verdicts and `barrier-match.json` have a single rater: me.
- **Component resolution is syntactic and root-based.**
  - Third-party components (Radix, Base UI, `next/link`) aren't followed.
  - Families are matched by name.
  - The mapping counterfactual tells a rule the tag but not the props a component adds, so its extras overstate what the components hide. The hand sample measures by how much.
- **The oracle is static.** No DOM, browser or axe-core is used, and the accessible name is a reduced computation. Focus order, focus visibility and how a particular screen reader voices a name aren't measured.
- **The history is a convenience sample**, limited by search terms. Several confirmed fixes are in files outside today's measured directories (Supabase's `packages/ui`, older shadcn paths), which `a11y-history.cjs` fetches directly.
- **Configuration details:**
  - The census's Oxlint config is `extends` only, as `rule-census.cjs` writes it, so react-doctor's settings aren't hoisted (as in earlier topics).
  - The Biome corpus run used a dedicated config with core's a11y rules.
  - The ESLint corpus run is filtered to accessibility rules, and the one crashing file was linted with `prefer-tag-over-role` off.

- **The oracle:**
  - **A** finds the element whose onClick calls `openTrigger`, then checks:
    - it's a native control, or has role, `tabIndex >= 0` and a key handler that calls `openTrigger` for both Enter and Space
    - it isn't hidden from assistive technology and has a name
    - clicking, the label, the icon and the children behave as before
    - `aria-expanded` is reported as a bonus, not required
  - **B** checks every swatch of the stroke and background pickers:
    - not hidden
    - a name that isn't a colour code or generic, and contains the swatch's palette name
    - five distinct names per picker
    - clicking calls `onChange` with the swatch's colour

    The canvas picker is reported but not judged: three of its picks are Radix colours with no name in the file.
- **What a DOM would add:** focus order on the page, focus visibility, and an axe pass. That needs jsdom (or happy-dom) and axe-core, which aren't installed. The experiment runner could add them outside the repo.
- **Stub noise:** the stubs add a few non-accessibility diagnostics of their own, such as ESLint `no-unused-vars` on `_`-prefixed stub parameters and Biome `noUndeclaredDependencies` on `react`. - **Alternates:**
  - **Excalidraw `CheckboxItem.tsx`** (sample a009): a `<button role="checkbox">` with no name. The rules object to the role, which the right fix keeps.

  - **Next.js `user-preferences.tsx`** (a024): unassociated labels, where `htmlFor` without an id, or a `<span>`, silences Oxlint.

## 11. Notes on Ultracite itself

These are raised for Hayden, not fixed.

1. **`no-autofocus` is off for React and on for Astro and Svelte, and no reason was ever recorded.**
   - In React it's off in all three linters.
   - It's on in Astro through `astro/jsx-a11y/no-autofocus`, and in Svelte through `svelte/valid-compile`'s `a11y_autofocus`.
   - It's been off since 2022 with no comment, and a test (f7025b12) locks Oxlint to ESLint's decision.
2. **The `label-has-associated-control` options exist only in ESLint's react preset.**
   - **Oxlint** runs the defaults: depth 2 and only `<label>`. It falsely reports labels nested three deep (calibration L08; 4 corpus labels, including Excalidraw's `PublishLibrary` fields), and misses custom `<Label>`s (L05; 17 corpus elements).
   - **Biome and the Astro preset** set no options either.
   - **The parity script** can't see an options-only gap.
3. **`control-has-associated-label` has the same name and different defaults.**
   - **ESLint** (jsx-a11y defaults) reports inputs even when a `<label>` wraps them or points at them: calibration L02 and L03, and E53, the right fix itself. That's 36 corpus elements.
   - **Oxlint** never reports inputs, so it misses a truly unlabelled one (L04).
   - jsx-a11y's own recommended config ships the rule with options.
   - Biome has no counterpart on.
4. **ESLint's jsx-a11y rules don't run on JSX in `.js` files.** The react block is scoped to `**/*.{jsx,tsx}`, while Oxlint and Biome check JSX wherever it is.
5. **The accessibility rule sets differ between linters beyond jsx-a11y.**
   - ESLint core turns on the github a11y and sonarjs table rules for every file. Oxlint gets them only through the opt-in js-plugins preset.
   - ESLint react turns on 20 react-doctor accessibility rules; Oxlint js-plugins turns on 7. The gap is acknowledged in `compare-rule-parity.ts` L242-243.
   - The rule that catches an Enter-only "button" (`role-button-requires-complete-keyboard-activation`) is ESLint-only.
6. **Templates.**
   - Oxlint has no template accessibility at all.
   - ESLint has it for Astro and Svelte, but not Vue or Angular (no vuejs-accessibility or `@angular-eslint/template` plugin).
   - Biome covers `.vue`, `.svelte` and `.astro` only with the framework preset, and core alone lints plain `.html`, Angular templates included, without understanding `(click)`.
   - For a Vue or Angular project, Biome is the only linter that checks templates.
7. **Biome 2.5.15's unsafe fixes can hang or break code** (`ultracite fix --unsafe`). Two upstream bugs to report:
   - `<div aria-activedescendant>` loops forever between `useAriaActivedescendantWithTabindex` and `noNoninteractiveTabindex`.
   - `noDistractingElements` turns `<marquee>News</marquee>` into `News</marquee>`.

   Biome's unsafe a11y fixes also delete a misspelled `aria-*` attribute rather than correct it, losing the reference.
8. **ESLint can crash on real code.** `jsx-a11y/prefer-tag-over-role` (6.10.2) throws on an object-valued `role` prop on a component, which aborts the ESLint run. One Supabase Studio file does this (jsx-eslint/eslint-plugin-jsx-a11y#1102, open). jsx-a11y also applies the rule to custom components (#1057, open).
9. **`oxlint --fix-dangerously` makes fake buttons focusable.**
   - It adds `tabIndex={0}` to a `<div role="button" onClick>` with no key handler, which makes it focusable but still not operable.
   - It fills an empty `onKeyDown` with `/* empty */`, which makes the evasion look deliberate.
   - It writes `tabIndex="0"` as a string.
10. **The template's keyboard line points at the evasion.**
    - "Include keyboard event handlers alongside mouse events" is the cheapest edit that silences `click-events-have-key-events`, and the one that doesn't fix the barrier. "Use semantic elements … instead of divs with roles" is the right advice.
    - "Use proper heading hierarchy" has no rule behind it.
    - The template puts accessibility under "React & JSX", though Biome applies it to every project.
    - The skill's copy has dropped "Accessibility" from its "User experience" item.
11. **The docs overstate core.** `configuration.mdx` L34 says the core preset enables a11y rules. That's true for Biome only: Oxlint core has none, and ESLint core has 9.
12. **`prefer-tag-over-role` and `useSemanticElements` are the noisiest rules.**
    - They make up 171 of Oxlint's 521 default-preset hits, and 26 of the 29 sampled sites were deliberate.
    - They fire on the correct ARIA button pattern, so an agent that implements it correctly is still told to change it.
    - Oxlint's and ESLint's versions also fire on custom components.
13. **Oxlint's `lang` also reports a missing `lang`** on `<html>`, so it duplicates `html-has-lang` (5 corpus sites).

Also noted, not part of this work: `research/bibliography/accessibility.md` and a one-line change to `research/bibliography/README.md` appeared in this worktree during the session (18:31), apparently from a parallel literature session. They were left untouched.

## 12. Reproducing

```sh
bash research/corpus/scripts/clone.sh && bash research/corpus/scripts/a11y-clone.sh
node research/corpus/scripts/a11y-run-all.cjs   # about 7 min; --skip-history skips the gh downloads
```

In order:

1. `a11y-inventory`
2. `-census`
3. `-linters --calibration --autofix --corpus`
4. `-disagreements`
5. `-markers`
6. `-jsx-census --lint`
7. `-sample --worksheet --print`, which reuses the frozen `sample.json`
8. `-sample --compute`, which needs `out/accessibility/labels-*.json`
9. `-history` (needs gh or curl)
10. `-examples`
11. `-tables`

- **Hand inputs:** `history.json`, `history-verdicts.json`, `decision-history.json`, `barrier-match.json`, and the rater labels kept in `classifications.json`.
- **Reruns match.** A full rerun reproduces `classifications.json`, `rule-census.json` and `jsx-census.json` exactly, apart from `generated` and timings. Counterfactual rows are sorted, because Oxlint's output order varies.
- **Two backwards-compatible changes to shared scripts:**
  - `collect-files.cjs` reads extra repo lists from `CORPUS_REPO_LISTS` and exports `config`.
  - `rule-census.cjs` uses that `config` and accepts `--files jsx`.

  Run with and without the changes on the same inputs (core + react + js-plugins over zod, hono, excalidraw and ultracite), `rule-census.json` and `rule-census.md` are byte-identical apart from the date and timings. The per-hit files differ only in order.
