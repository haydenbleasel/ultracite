# Dead code and duplication in real TypeScript codebases: measurement report

The data behind the dead-code and duplication post, measured on 2026-10-12. Generated tables are in `tables.md`. The machine-readable results are:

- `inventory.json`, `rule-census.json` and `rule-census.md`
- `linters.json`: the calibration matrix with every message and help text, what each linter's fix pass does to each case, and ESLint and Biome on the corpus
- `disagreements.json`
- `typed-census.json`, `exports.json`, `clones.json` and `markers.json`
- `sample.json` and `classifications.json`
- `history.json` and `history-lint.json`
- `decision-history.json`

The agent-experiment subjects are in `corpus/examples/dead-code/`. Everything is regenerated by `research/corpus/scripts/dead-code-*.cjs` (see §10).

"Dead-code rule" here means a rule about code that has no effect:

- **Unused names:** variables, imports, parameters, private members, labels and collections declared and never read.
- **Dead values:** dead stores, useless assignments, unused expression statements and ignored return values.
- **Unreachable code:** code after `return`/`throw`, loops that can't iterate twice, and constant or duplicate conditions.
- **The `no-useless-*` family.**

"Duplication rule" means a rule about repeated code: identical functions, branches, expressions and strings, and duplicate imports, keys, cases and members. The catalogue is in `dead-code-lib.cjs`.

## TL;DR

- **Corpus.** The same 8 codebases, SHAs and 3,333 files (694,309 lines) as the earlier reports. Ultracite's own CLI is listed separately.

- **What Ultracite turns on.**
  - **Oxlint's default presets (core + react)** enable 38 dead-code and duplication rules. Two of them, `typescript/no-duplicate-type-constituents` and `no-useless-default-assignment`, need `--type-aware`.
    - Unused names: `no-unused-vars`, `no-unused-private-class-members`, `no-unused-labels`, `no-unassigned-vars`.
    - Unreachable code: `no-unreachable`, `no-unreachable-loop`, constant and duplicate conditions.
    - `no-unused-expressions`, the `no-useless-*` rules, and duplicate imports, keys and cases.
    - There is no dead-store, identical-function, duplicated-branch or duplicate-string rule. Those are in the opt-in js-plugins preset, which adds 22: 21 sonarjs rules and `github/no-useless-passive`.
  - **ESLint's core preset** enables 89 (6 more with type-aware, 3 more for `.tsx` with react). 33 are on in no Oxlint preset:
    - `no-useless-assignment`, which is nursery in Oxlint 1.86.0
    - sonarjs `unused-import` and `prefer-immediate-return`
    - unicorn rules Oxlint hasn't ported, such as `no-useless-else`, `no-unused-properties`, `no-duplicate-if-branches` and `no-unused-builtin-method-return`
  - **Biome** enables 44. It has no rule for dead stores, identical functions, duplicated branches or duplicate strings, and Ultracite runs `noUnusedImports` with a safe autofix.
  - **No linter checks unused exports.** ESLint's `import-x/no-unused-modules` is off, and no shipped tsconfig sets `noUnusedLocals`.

- **Ultracite sets no `no-unused-vars` options, so the three linters don't agree on what "unused" means.** On the same code, the calibration finds:
  - **Oxlint** skips `_`-prefixed variables, parameters and imports. It still reports a parameter named exactly `_`, every catch binding (`_error` included) and rest-sibling omits, and it skips the parameters of `override` methods.
  - **typescript-eslint** (ESLint's defaults) has no ignore pattern, so it reports `_x`, `_` and `_error` alike.
  - **Biome** skips `_` names and rest siblings, but reports every unused parameter, including those before a used parameter. It also reports `_`-prefixed imports.
  - On the corpus, typescript-eslint reports 735 unused names, Oxlint 396 and Biome 426. 314 names are reported only by ESLint because they start with `_`.

- **The diagnostic names the rename that silences it.**
  - Oxlint: "Variable 'x' is declared but never used. Unused variables should start with a '_'." The help is "Consider removing this declaration.", or "Did you mean to use this variable?" when the variable is assigned later and never read.
  - sonarjs: "…or rename it to "_x" to make intention explicit."
  - Biome's terminal: "If this is intentional, prepend x with an underscore". Its JSON reporter, which is what the agent handoff reads, carries only "This variable x is unused."
  - Renaming to `_x` silences Oxlint and Biome. typescript-eslint, `sonarjs/no-unused-vars` and TypeScript's `noUnusedLocals` still report it.
  - `void x;` silences every unused-name rule in every linter. Only Biome's `noVoid` and ESLint's `sonarjs/void-use` object to the `void` itself.

- **How often the rules fire.** 2,378 dead-code and duplication diagnostics in 694,309 lines (34 per 10,000; 2.7% of everything the presets report), 1,463 of them from the default presets. Maintainers suppress almost none: raw minus reported is 9. Top rules (raw):
  - `no-unused-vars` 396
  - `sonarjs/no-duplicate-string` 344
  - `sonarjs/no-unused-function-argument` 342
  - `unicorn/no-useless-undefined` 293
  - `no-duplicate-imports` 289

- **What the unused names are** (96 sampled across every repo, raw mode; a blind second rater gave the same label to 19 of 20 and agreed on all 20 about whether the code should change):
  - 79 are intentional: interface-conformance and callback placeholder parameters, type parameters, destructuring omits, the `_` convention.
  - 13 are leftovers, safe to delete, and 1 is debug instrumentation.
  - 3 are false positives: two `using` declarations, where disposal is the point, and a `const enum` used only in a type.
  - **None signals a bug.** Of 50 sampled dead stores, 42 are leftovers (mostly an initializer every branch overwrites), 8 are deliberate GC releases, and **none is a bug**.

- **The bug-shaped unused variable is real, but rare and caught by little.** The history search ran 165 searches plus a diff-shape scan of 6,598 small fix PRs, and confirmed 18 fixed bugs:
  - 6 values that should have been used
  - 6 lost return values
  - 5 inconsistent clones
  - 1 shadowing bug that made a branch dead

  Linting each file before its fix, a dead-code rule fires on the buggy lines of 3:
  - ESLint's `no-useless-assignment` on the dead initializer next to the bug in microsoft/vscode#247184
  - `sonarjs/no-empty-collection` on the never-filled cache in excalidraw/excalidraw#880
  - the ignored parameter in microsoft/vscode#282685, caught by `sonarjs/no-unused-function-argument`, Biome and `tsc` (Oxlint's and ESLint's `no-unused-vars` skip a parameter before a used one)

  Oxlint's default presets flag none of the 18. No rule reports a lost return value or any of the 5 inconsistent clones.

- **What the fix pass does before an agent sees anything** (calibration):
  - `oxlint --fix-dangerously`, which `ultracite fix --unsafe` passes, deletes an unused `const x = compute()` together with the call, and deletes `using` declarations.
  - It renames unused parameters to `_x`, and renames `_` to `__`.
  - It deletes the omitted key from a rest-sibling omit (`const { secret, ...rest } = obj`), so `rest` now contains `secret`.
  - `biome check --write --unsafe` prefixes every unused name with `_`.
  - Both turn the bug shape (`const normalized = normalize(input); return validate(input)`) into something no rule reports.

- **TypeScript's own checks** (`noUnusedLocals` + `noUnusedParameters`, per-repo tsconfig) report 361 unused declarations.
  - Zod, Astro, Vite and VS Code already turn on `noUnusedLocals`, and tRPC and Vite lint with `^_` ignore patterns. So unused names concentrate in Excalidraw, Next.js and VS Code.
  - TypeScript and the lint rules overlap only partly. TypeScript reports `_` locals but not `_` parameters, never reports catch bindings or rest siblings, and reports every parameter before a used one.

- **Unused exports and files** (one TypeScript program per repo, no installs; Zod, hono, tRPC, Vite, Astro, Excalidraw):
  - Of 8,177 exports, 111 have no resolvable reference and aren't reachable from a `package.json` entry point.
  - Hand-checking 89 candidates found:
    - 47 dead, including two whole files: Zod's `v4/core/zsf.ts` and Astro's `vite-plugin-astro-server/resolve.ts`
    - 18 used by name at runtime
    - 16 public API the entry-point mapping missed (virtual modules, JSR exports)
    - 7 self-registering actions
    - 1 miss by the analysis (since fixed)
  - 1,794 exports are used only through the entry points. Without them, an analysis would call that public API dead.

- **Duplication** (token clone detector, 50 tokens and 5 lines, jscpd's defaults):
  - In source, exact (Type-1) clones cover 4.5% of code lines, and 15.2% with identifiers and literals normalised (Type-2). At 100 tokens (maven-pmd-plugin's default) the shares are 1.5% and 6.8%.
  - Tests are far more duplicated (Type-2 54.8%), and so is vendored code (96.7%, mostly Next.js's compiled bundles).
  - Type-2 runs from 3.1% (Vite) to 56.9% (Zod, whose v4 locale files share one shape).

- **The duplication rules see a sliver.**
  - `sonarjs/no-identical-functions` only compares same-file functions whose token-identical bodies span 3 or more lines, in three kinds of node. The detector reproduces its 25 corpus hits exactly.
  - At that threshold, source has 168 Type-1 function-clone classes. The rule can see 20: 95 are in different files, and 53 are callbacks, object methods or class properties. Another 534 classes differ only in names or literals.

- **What the clones are** (46 sampled; the second rater agreed on 14 of 20, κ 0.57): 20 accidental copy-paste, 13 trivial, 11 deliberate, and **2 inconsistent copies that are bugs**.
  - **Zod v3's bigint "too small" message says "Number must be".** `sonarjs/no-duplicated-branches` flags it, and merging the branches, the cheap fix, would lock the wrong word in.
  - **Excalidraw's multi-selection drag handler** commits frame membership only for the first element.
  - In 28 of the 46, the right fix isn't the one the lint message suggests. In 20 of those, the right fix is to leave the code alone.

- **Calibration:** 86 cases with every message and help text (§5).

## 3. Method

### 3.1 Inventory (`dead-code-inventory.cjs`)

- **Oxlint:** `core`, `react` and `js-plugins`, including test-file overrides. Type-awareness, fix kind and category come from `oxlint --rules`.
- **ESLint:** `calculateConfigForFile` on a `.ts`, `.tsx`, `.js` and `.test.ts` path, for core alone, core + type-aware, and core + react. These are the options a file actually gets: ESLint 10 materialises base-rule defaults, and typescript-eslint applies its defaults inside the rule.
- **Biome:** `core` and `react`, plus Biome's recommended set (the presets don't turn `recommended` off), and `biome explain` for each rule's fix kind and options.
- **Concepts:** a table lines up each concept across Oxlint core, js-plugins, ESLint, Biome and TypeScript.

### 3.2 Census (`dead-code-census.cjs` → `rule-census.cjs`)

Core + react + js-plugins, in both modes, with every dead-code and duplication rule those presets enable as focus rules (60).

- **Reported** honours in-file disable comments.
- **Raw** neutralises `eslint-` and `oxlint-disable` comments. `biome-ignore` and `@ts-expect-error` aren't neutralised; `dead-code-markers.cjs` counts them.

### 3.3 Calibration (`calibration/dead-code/`, `dead-code-linters.cjs --calibration --autofix`)

86 cases:

- `cases.ts`: unused names, dead values, unreachable code, silencing
- `imports.ts`
- `duplication.ts`
- `strings.ts`, plus a `strings.test.ts` copy for the test-file override

They ran through six configurations: Oxlint core + react, Oxlint + js-plugins, ESLint core untyped and type-aware, Biome core, and `tsc`.

- **Recorded:** every message, Oxlint `help`, ESLint suggestions, and Biome's terminal notes, which its JSON reporter omits.
- **`--autofix`:** runs each fix pass `ultracite fix` uses on copies of the cases and records the lines removed and added per case: `oxlint --fix` and `--fix-dangerously`, `eslint --fix`, and `biome check --write` and `--write --unsafe`.

### 3.4 Three linters on the corpus (`--corpus`, `dead-code-disagreements.cjs`)

ESLint and Biome ran on the census's raw mirror. Every line reported by some linters and not others is recorded for each shared concept, then classified from the AST at that line: a `_` prefix, a parameter before a later parameter, a rest sibling, a catch binding, a `satisfies` statement, an initializer, or a type import.

### 3.5 TypeScript (`dead-code-typed.cjs`)

Every TypeScript file was checked with its nearest tsconfig plus the four flags. The checks don't depend on resolving imports, so they're complete even without dependencies. The results are compared with each linter by file, line and name.

### 3.6 Unused exports and files (`dead-code-exports.cjs`)

One TypeScript program per repo covers the measured package, its tests and the sibling packages that consume it, with no `node_modules`.

- **Resolution:** TypeScript's own, with the package's tsconfig (including `paths`) and bundler resolution. A fallback maps workspace package names through their `package.json` `exports` to source, and maps relative imports of built output (Astro's tests import `../dist/…`) back to `src/`.
- **References:** every identifier naming an export, or naming an import's local binding, is resolved with the checker to its declaration.
  - Uses in other files count. Import and export declarations are wiring and don't.
  - Shorthand properties, namespace members and type references count.
  - `.astro`, `.vue`, `.svelte`, `.mdx` and `.html` files are scanned for imports with a regex.
- **Entry points:** every string in `exports` (all conditions), `main`, `module`, `types` and `bin`, mapped from `dist/` back to `src/`, plus Vite's build entries.
  - Everything an entry exports, following `export *` and `export * as ns`, is public API.
  - Wildcard subpaths are tracked separately, because Excalidraw's map every file to type declarations.
- **Classification:** each export of a measured file gets the first match of: used in source, public API, used elsewhere, dynamic (`import()`, `typeof import()`, a file loaded by a path string), own-file-only, or unreferenced. Unreferenced names are grepped as whole words across the clone.
- **Two fixes made after the hand check:**
  - shorthand properties had been skipped as declaration names, found through tRPC's `getBody`;
  - symbols are now keyed by declaration, so interfaces merged by module augmentation match.

  Together these cut the candidates from 124 to 111. The hand-checked sample is kept as drawn (§3.8).

### 3.7 Clone detector (`dead-code-clones.cjs`)

Tokens come from typescript-estree, so layout and comments are already gone. Import and re-export declarations are dropped.

- **Normalisation** follows Svajlenko and Roy (arXiv:2006.15682):
  - Type-1 compares exact tokens.
  - Type-2 replaces identifiers (including JSX names and contextual keywords) with `ID`, and string, number, regex, bigint, template and JSX-text literals with `LIT`. Keywords, operators, `true`, `false`, `null` and `this` stay.
- **Windows:** rolling hashes over every 50-token window, verified token by token.
  - Identical windows that don't overlap are chained into maximal clone classes, kept only if every fragment spans at least 5 lines.
  - Duplicated lines are the code lines inside any fragment, copies included.
- **Thresholds, pinned:**
  - 50 tokens and 5 lines are jscpd's defaults (`docs/rust.md` at kucherenko/jscpd `19f2c885`).
  - 100 tokens is maven-pmd-plugin's CPD default (`CpdReport.java` at apache/maven-pmd-plugin `8250c2ab`). PMD's own CLI requires `--minimum-tokens`.
  - Svajlenko and Roy give 30–100 tokens and 6–15 lines as typical minimums.
  - CCFinder's manual makes the minimum length mandatory, with no default. The TSE 2002 paper was read-protected, so its value isn't cited.
- **Functions:** whole function bodies, Type-1 and Type-2, of 50 or more tokens, with nested clones folded into the outermost class.
  - The subset `sonarjs/no-identical-functions` can see is computed separately: same file, Type-1 body of 3 or more lines without the braces, and only function declarations, functions assigned to variables and class methods.
  - Checked against the rule's real hits: 25 of 25 match, with no extras.
- **Branches:** identical bodies within one if/else-if chain or switch, split by whether the body spans more than one line.
- **File categories:**
  - **source:** the corpus.
  - **test:** test, fixture, mock, bench, example and story files.
  - **vendored:** `vendor`/`compiled`/`bundles`/`polyfills`/`dist` directories, third-party licenses and repo-specific exclusions.
  - **declaration:** `*.d.ts`.
- **Skipped:** minified or huge files (over 1 MB, or a mean line over 300 characters). That's 140 files (18.5 MB) of Next.js's `compiled/`, 3 Excalidraw files and 1 Astro file. 2 of them are corpus source files left out of the denominator.

**Populations** (raw mode):

**Codebooks** (in `classifications.json`):

- **Unused names and dead stores:** leftover, intentional, debug-wip, bug (needs a concrete runtime consequence), false-positive, unclear.
- **Clones:** accidental, deliberate, inconsistent, trivial, unclear, plus the cheap fix and the right fix.
- **Exports:** dead, unnecessary-export, public-api, dynamic, test-or-tooling, analysis-miss, unclear.

**Raters.** One Claude subagent per kind classified every site, with about 26 lines of context and read-only access to the clones. A separate Claude subagent labelled a seeded subset of 20 per kind blind. Both raters are Claude models, so agreement measures how consistently the codebook applies.

| exports | 20 | 20 | 1.00 | 20 | 1.00 |

- **Unused names:** the one disagreement is tRPC's `using _finally`, false-positive against intentional. κ is low because one category dominates.
- **Clones:** all six disagreements are accidental against trivial or deliberate on small mirrored pairs. The first rater had flagged them as judgment calls.

### 3.9 History (`history.json`, `dead-code-history.cjs`)

- **Search.** A Claude subagent searched each upstream repo with `gh`. It ran 165 searches of PR titles and bodies, issues and commits, each listed with its hit count in `searched`. The terms covered:
  - unused, never-used and never-read; dead code; unreachable
  - wrong, typo'd or shadowed variables; ignored or lost return values
  - copy-paste, "same fix", "missed"; `noUnusedLocals`, `no-unused-vars`
- **Diff-shape scan.** GraphQL fetched every merged PR with "fix" in the title: zod, hono and tRPC since 2018; Vite, Astro, Excalidraw and Next.js since 2020; VS Code 2021–2026. It kept the 6,598 tiny ones (1–2 source files, 1–6 lines changed) and downloaded their patches. 421 hunks were flagged and read: an added line starts using an identifier already in the hunk, starts using a call's result, or removes an exit statement.
- **Selection.** Only merged fixes of behavioural bugs count: 18 confirmed, 17 rejected, and 12 lint-driven cleanups noted separately.
- **Verification.** For each bug, the diff was read, the merge checked, and the buggy lines located at the fix's parent commit.
- **Lint.** `dead-code-history.cjs` downloaded each buggy file at the parent commit, through `gh api`, or `raw.githubusercontent.com` once the REST quota ran out. It linted each file with all five configurations and recorded every rule on the buggy lines. Type-aware ESLint was added by hand for microsoft/vscode#120054.
- **Coverage gaps.** VS Code PRs merged in 2026 were listed but their patches weren't scanned. VS Code before 2021 and Next.js in 2021-H2 weren't scanned at all.

`git log -S` on every rule name, the changelog and changesets, and `gh issue/pr list` on haydenbleasel/ultracite (§9).

## 5. Calibration

86 cases; the full matrix is in `tables.md` §3. Here is what default Oxlint misses.

- **Dead stores:**
  - V02 (overwritten before read), V03 (the last store), V05 (the bug shape as a dead store) and V11 (`return count++`).
  - These need `sonarjs/no-dead-store`, `no-useless-increment` or ESLint's `no-useless-assignment`.
- **Unused collections:**
  - V07 needs `sonarjs/no-unused-collection`.
- **Ignored return values (V08):**
  - `items.concat(…)` and `items.map(fn)` used as statements are caught only by ESLint's `unicorn/no-unused-builtin-method-return` and the type-aware `sonarjs/no-ignored-return`.
  - `input.trim()` is caught by nothing without types.
- **Duplication:** every case except duplicate imports needs js-plugins or ESLint.
  - `no-identical-functions` misses 2-line bodies (D07), renamed identifiers (D10), changed literals (D11), object methods (D12) and inline callbacks (D13). It catches 3-line bodies, arrows assigned to variables and class methods.
  - `no-duplicated-branches` misses single-line branches (D03).
  - `no-duplicate-string` needs 3 occurrences of 10 or more characters. It ignores strings used as object keys and is off in tests (X01–X05).
  - `sonarjs/no-identical-expressions` doesn't report `a === a` (D15).
- **Unused exports (D01):** nothing catches them.

## 6. Findings worth stating carefully

- **An unused variable is almost never a bug in maintained code, but the rare bug looks exactly like a leftover.**
  - None of 96 sampled unused names and none of 50 dead stores was a bug.
  - The history has real ones, but only one of them trips a dead-store rule, and that one is ESLint-only. Both the help text and the fix pass push toward deleting or renaming.
- **"Unused" isn't one rule.** With no options set, the three linters disagree on:
  - `_` names and catch bindings
  - rest siblings and leading parameters
  - `override` parameters and `_` imports

  The `_` rename the message suggests works only in Oxlint and Biome, and not for catch bindings or a parameter named `_` in Oxlint.
- **The duplication rules are narrow by construction.**
  - 9 in 10 exact function clones and every renamed one are out of reach.
  - The one inconsistent clone in reach was the Zod bigint message, and the rule's suggested fix would have hidden it.
- **Unused exports are mostly public API.** 1,794 are reachable only from entry points.

## 7. Caveats

- **Snapshot.**
  - The repos are at their 2026-10-10 HEADs.
  - Next.js is 40% of the source lines.
- **Libraries that already run these checks.** Seven of the eight are libraries. App code likely has more leftovers.
- **The classification is judgment.**
  - It was made by LLM raters with codebooks.
  - A bug needs a concrete consequence, so subtle ones may be labelled leftover.
  - 65 of the 96 unused-name sites are `_` names that only ESLint reports. Of the 35 Oxlint reports, 25 are intentional and 10 leftovers.
- **The unused-export analysis is static.** Registries, virtual modules and generated code were a third of the candidates. Next.js and VS Code weren't measured.
- **Clone windows aren't scope-aware**, as in jscpd. Function and branch clones are.
  - 2 corpus source files with very long lines were skipped.
  - Tests count only inside the measured directories.
- **The fix-pass results come from the calibration cases.** The rest-sibling deletion was checked on probes, not the corpus.
- **The history is a convenience sample.**
  - It's limited by search terms and the GitHub rate limit.
  - The rule verdicts come from linting each buggy file as it was before the fix, without types, except vscode#120054.

## 9. Notes on Ultracite itself

These are raised for Hayden, not fixed.

1. **`no-unused-vars` defaults differ by linter, and the parity check can't see it.** No core preset sets options.
   - Oxlint skips `_` names but reports bare `_` parameters and every catch binding.
   - typescript-eslint reports all of them: 314 extra names, and 370 unused `_` bindings.
   - Biome skips `_` names and rest siblings.

   `compare-rule-parity.ts` compares only options Oxlint spells out. The opt-in `gdp` ESLint preset already sets `argsIgnorePattern: "^_"`, "matching oxlint's default". Shared options would make one convention hold, for example `^_` for args, vars, caught errors and destructured arrays, plus `ignoreRestSiblings: true`.
2. **`ultracite fix --unsafe` with Oxlint changes behavior** (§4.3).
   - It removes keys from rest-sibling omits; 76 corpus lines have the pattern.
   - It deletes declarations along with their initializer's call, and deletes `using` declarations.
   - It renames `_` to `__`.

   `ignoreRestSiblings: true` would prevent the first.
3. **Biome's advice never reaches the agent.** The JSON reporter's `advices` is empty, so the agent gets "This variable x is unused." with no help, and an unnamed "This import is unused."
4. **Dead stores need js-plugins on Oxlint.** Oxlint's defaults report none of the 37 to 143 dead stores ESLint core reports. The same is true of identical functions, duplicated branches and duplicate strings.
5. **33 dead-code rules are ESLint-only.** `unicorn/no-useless-else` alone reports 732 corpus sites.
6. **Biome's `noUnusedExpressions` reports `x satisfies never;`** (146 corpus sites), which ESLint and Oxlint allow.
7. **Biome reports private-member diagnostics twice** while `style/useReadonlyClassProperties` is on, as it is in Ultracite's core. Bisected to that rule with Biome 2.5.15; upstream behaviour.
8. **Oxlint's `no-unused-private-class-members` checks `#private` only.** TS `private` members are caught by ESLint, Biome and `tsc`.
9. **typescript-eslint and `sonarjs/no-unused-vars` report `using _x = …`.** Its disposal is the point, and these are 2 of the 3 false positives in the sample.
10. **Nothing checks unused exports.**
    - `import-x/no-unused-modules` was a no-op until 2026-07-04, then turned off.
    - No shipped tsconfig sets `noUnusedLocals` or `noUnusedParameters`.
11. **No rationale was recorded** for turning any of these rules on. They came in through blanket every-rule policies:
    - ESLint #115 in 2023, and V7
    - Biome `"all": true` (#140), then an explicit list in v5 (#162)
    - Oxlint categories in V7, then an explicit list (#660)

    The two exceptions:
    - **The `no-duplicate-string` test override** (dfe0f015, 2026-07-05, "Fix lint issues"). Its only rationale is the code comment: "Repeated string literals (test titles, expected values) are normal and idiomatic in test files."
    - **Biome's safe `noUnusedImports` fix** (#294).
12. **The agent hook's unused-import exception (#483) covers Biome only.** ESLint's `unused-imports` autofix still runs in hooks.
