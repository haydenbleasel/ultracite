# Cognitive complexity in real TypeScript codebases: measurement report

The data behind `/blog/cognitive-complexity`, measured on 2026-10-10. Machine-readable numbers are in `results.json`, and `tables.md` has the generated tables. Everything here is regenerated by the scripts in `research/corpus/scripts/` (see §10).

At the time, Ultracite set a cognitive complexity limit of 20: Biome's `noExcessiveCognitiveComplexity` with `maxAllowedComplexity: 20`, and `sonarjs/cognitive-complexity: ["error", 20]` in the ESLint preset. It also enabled the cyclomatic `complexity` rule at its default maximum of 20. Sonar's and Biome's own defaults are 15.

## TL;DR

- **Corpus.** The 8 open-source TypeScript codebases contain 30,904 functions in 3,333 files (694,309 physical lines). The codebases are zod, hono, tRPC, Vite, Astro, Excalidraw, Next.js (`packages/next/src`, all of it) and VS Code (`src/vs/editor/common`). Ultracite's CLI is reported separately. All files parsed, and every rule report was joined to a function.
- **Most functions are trivial.** Of all functions, 55.16% score 0 and 33.53% score 1–5. The median is 0, p95 is 12 and p99 is 35.
- **Over the limits.** 1,147 functions (3.71%) score over 15, 802 (2.60%) over 20, and 535 (1.73%) over 25.
- **15 versus 20.** A limit of 15 flags 345 more functions than 20, which is 43% more (×1.43). That's 640 files with a flagged function instead of 503. The per-repo ratio ranges from 1.10× (zod) to 1.75× (Astro), with a median of 1.41×.
- **Cyclomatic versus cognitive.** The two metrics are strongly rank-correlated: Spearman ρ = 0.926 over all functions and 0.862 over functions with cognitive > 0. They still disagree at the limit. Of the 802 functions over cognitive 20, 312 (38.9%) are not over cyclomatic 20. Of the 601 over cyclomatic 20, 111 (18.5%) are not over cognitive 20.
- **Example extremes.**
  - VS Code's `toLabel`, a flat 29-case switch, scores cyclomatic 30 and cognitive 1.
  - A 61-line Next.js callback nests 13 levels deep and scores cognitive 87 with cyclomatic 18. The cyclomatic rule passes it.
  - Next.js's `createMetadataElements` is the corpus maximum at cognitive 989 (1,551 lines).
- **Biome and sonarjs don't agree on scores.** Where either tool shows a score of 2 or more, they match exactly only 32% of the time. At the same nominal limit of 20, Biome flags 1,082 functions where sonarjs flags 787 (1.37×), so Biome at 20 is about sonarjs at 16. Ultracite's preset comment ("Matches Biome's noExcessiveCognitiveComplexity limit") is true of the number but not of the behaviour.
- **Ultracite dogfood.** 4 of its 712 CLI functions score over 20 (max 52). Ultracite's own repo applies neither rule to itself: `oxlint.config.ts` sets `complexity: "off"` and doesn't load the sonarjs JS-plugin preset.
- **Implementation quirks** (minimal reproductions in `calibration/`):
  - sonarjs 4.2.2 scores `||` and `??` as 0, which contradicts the whitepaper.
  - sonarjs leaks +1 nesting after `cond ? () => … : …`.
  - Biome skips getters and setters.
  - Biome caps scores at 255.
  - Biome loses a nesting level after every nested `if … else`.

## 3. Method

### 3.1 Unit of analysis and denominator

The denominator comes from a local rule, `census/functions` (`scripts/census-plugin.cjs`). It hooks ESLint's `:function` selector, which matches `FunctionDeclaration | FunctionExpression | ArrowFunctionExpression`. That is exactly the selector sonarjs's rule hooks (`':function'` / `':function:exit'`). It is also exactly the set of nodes for which ESLint's code-path analysis opens a `"function"` path, which core `complexity` scores. So all three use the same unit:

- declarations, expressions and arrows
- class and object methods, accessors and constructors (their bodies are `FunctionExpression`s)
- class-field arrows
- callbacks

In the 8 repos that is 8,197 arrow callbacks, 8,107 declarations, 6,284 other arrows, 4,765 methods, 1,447 object methods, 839 constructors, 540 getters and setters, 373 class-field arrows and 352 other function expressions.

Mismatches:

- **Score 0 is silent.** sonarjs reports nothing for a score of 0, so those functions come only from the census.
- **Core `complexity` also scores non-functions.** It reports class-field initializers (1,394 in the 8 repos) and static blocks (0). These are excluded from all per-function numbers.
- **Bodiless TypeScript signatures** (overloads, abstract methods, `declare`) are functions to none of the three.

### 3.2 Joining reports to functions

For each function, the census computes the location each rule reports at:

- sonarjs uses its own `getMainFunctionTokenLocation` helper: the name, the `function` keyword or `=>`.
- core `complexity` uses ESLint's `getFunctionHeadLoc`.

Both helpers are loaded from the installed packages, and the join is on the exact start and end position. **Result: 0 unmatched reports, 0 duplicate keys and 0 functions without a cyclomatic score, in every repo.**

### 3.3 How eslint-plugin-sonarjs attributes nested functions

**Every function, including each callback, is scored and reported separately, using only its own increments. Nesting restarts at 0 at each function boundary. A callback's score never counts toward its enclosing function.**

In `cjs/S3776/rule.js` (4.2.2):

- `onEnterFunction` pushes a fresh `[]` onto `functionOwnComplexity` and `0` onto `functionOwnControlFlowNesting`.
- Increments go to `last(functionOwnComplexity)` with nesting `last(functionOwnControlFlowNesting) + 1`.
- `onLeaveFunction` calls `checkFunction()` for every function with its own list.

The older whitepaper-style aggregation (`complexityIfNested` for second-level functions) is still in the file. It only feeds the file-level metric (`metricsSink.cognitiveComplexity`) and never produces issues.

Calibration confirms it:

- **C1:** `for { if { row.forEach(x => { if (x) … }) } }` scores 3 for the outer function and 1 for the callback. The same logic inlined as a loop (C2) scores 6.
- **C12:** three nested functions with one `if` each score 1, 1 and 1.

This matters here because 42% of functions are nested, and 27.8% of the functions over 20 are nested functions scored on their own.

**Sensitivity.** Count each top-level function's own score plus every descendant's own score. That ignores the whitepaper's extra nesting, so it is a lower bound. On that count, 898 top-level functions would be over 20 instead of 579: at least 55% more.

### 3.4 What sonarjs 4.2.2 actually counts

| Construct | Whitepaper | sonarjs 4.2.2 |
| --- | --- | --- |
| `if`, loops, `catch`, `switch`, `?:` | +1, plus nesting | +1, plus nesting |
| `else`, `else if` | +1 | +1 |
| `switch` cases, `try`, `finally` | free | free |
| labelled `break`/`continue` | +1 | +1 |
| `&&` sequence | +1 | +1 |
| **`\|\|`, `??`** | +1 per sequence | **0**. `a \|\| b \|\| c` scores 0, and `(a && b) \|\| (c && d)` scores 2. |
| JSX `cond && <X/>` | (not covered) | 0 (exempt) |
| recursion | +1 | **0** |
| `\|\|=` `&&=` `??=` | (not covered) | 0 |
| nested function | counts toward parent, +1 nesting | separate, nesting reset |

**A nesting leak.** When a function is directly a ternary branch (`a ? () => 1 : null`), the rest of the enclosing function is scored one level too deep, once per such branch.

- `h3`: should score 2; sonarjs reports **3**.
- `h4`: two function branches, then `for { if }`, should score 4; sonarjs reports **8**.
- Biome gets both right. Wrapping the function (`(() => 1) as F`) avoids the leak.

The likely cause is visitor ordering. The `'*'` handler runs before `':function'`, so the branch's nesting increment lands on the enclosing function's counter, and the decrement lands on the inner function's counter. This is inferred from the code and confirmed by the reproductions.

In this corpus, 60 functions contain the pattern, and 13 of them score over 20. Their scores are reported as-is.

### 3.5 What ESLint core `complexity` counts (`variant: "classic"`)

The score starts at 1, then adds +1 for each of:

- `if`, `?:`, loops and `catch`
- **every non-default `case`**. The `modified` variant would count a switch as 1.
- **every** `&&`, `||` and `??`
- every default parameter or destructuring default
- every `?.`
- every logical assignment

There is no nesting term. For example, `f(a = 1, { b = 2 } = {}, o?) { return o?.p?.q ?? a + b }` scores cyclomatic 7 and cognitive 0.

## 6. Biome cross-check

### 6.1 Setup

The cross-check ran Biome 2.5.15 `complexity/noExcessiveCognitiveComplexity` with `maxAllowedComplexity: 1`, the lowest value Biome accepts. The config is `biome-config/biome.json` (`root: true`, VCS off), with `--only` set to the rule and the JSON reporter. It ran on all 9 repos.

- **Config-free mirror.** Biome 2 picks up nested `biome.json(c)` files inside the paths it lints even with `--config-path` (zod's own config broke the first run). So the source files are copied into a config-free mirror, `biome-input/<repo>/`, and Biome lints the copy.
- **Suppressions.** `biome-ignore` comments are neutralised with a same-length replacement, mirroring ESLint's `noInlineConfig`. There were 10 occurrences, and only one suppressed this rule (Ultracite's `upsertEditorConfig`).
- **Joining.** A diagnostic maps to the innermost function whose head span contains Biome's start position. Biome starts the range at the end of the previous line when a function begins on a new line, so those positions are moved forward. **Every diagnostic mapped.**
- **Parse errors.** Biome could not parse 15 VS Code files ("Decorators are not valid here", for parameter decorators). Their 561 functions are excluded from the comparison.
- **Hidden scores.** Biome only shows scores of 2 or more, so 0 and 1 can't be told apart. "Visible" means at least one tool shows 2 or more.

### 6.3 Why they differ

Each mechanism was isolated in `calibration/`. "WP" is the whitepaper value.

| Case | WP | sonarjs | Biome | Mechanism |
| --- | ---: | ---: | ---: | --- |
| callback in `for { if { … } }` with one `if` (C1) | outer 7 | outer 3, cb 1 | outer 3, cb **4** | **Nested functions.** Both score separately, but Biome starts at the enclosing nesting + 1 per function level; sonarjs resets to 0. |
| callback directly in body, two `if`s (D1) | (in parent) | 2 | **4** | same |
| `if (a \|\| b \|\| c)` (D4) | 2 | 1 | 2 | **`\|\|`/`??`.** Biome counts +1 per sequence; sonarjs doesn't. |
| `if (n ?? m)` (D2) | n/a | 1 | 2 | same |
| `(a && b) \|\| (c && d)` (C3) | 3 | 2 | 3 | same |
| `if` + `{show && <span/>}` (D10) | n/a | 1 | 2 | **JSX `&&`.** sonarjs exempts it. |
| `try {} finally {}` + two `if`s (H1) | 2 | 2 | **3** | **`finally`.** Biome adds +1. |
| `else if` chain nested two deep (E8) | 8 | 8 | **12** | **Nested `else if`.** Biome adds the nesting penalty. |
| `if { if {} else {} ; if (c) {} }` (G1) | 6 | 6 | **5** | **Nested `else`.** After a nested `if … else`, Biome scores the rest of the block one level too shallow. This is why Biome is ever lower. |
| two such blocks, then an `if` (G6) | 9 | 9 | **7** | same, compounding |
| getter or setter with two `if`s (E7) | 2 | 2 | **≤ 1** | **Accessors.** Biome doesn't analyse `get`/`set`. |
| `a ? () => 1 : () => 2`, then `for { if }` (H4) | 4 | **8** | 4 | **sonarjs nesting leak** (§3.4) |
| recursion, logical assignment, `switch`, labels, `catch`, plain `else` | n/a | same | same | agree |

## 7. Side check: oxlint `complexity`

Ultracite's oxlint core preset enabled `complexity: "error"` with the default max of 20. oxlint 1.86.0 ran on the same files with only `complexity` at max 0.

- **Over-20 counts are identical to ESLint's in all 9 repos.** For example, Next.js has 230 and Excalidraw 116.
- **Per-function scores** are identical for 96.4–100% of line-joined pairs.
- **The residual is a join artifact.** oxlint also reports class-field initializers spanning the same lines as class-field arrows.

The cyclomatic findings therefore carry over to the oxlint preset. Not tested: sonarjs running as an oxlint JS plugin (the `js-plugins` preset).

## 9. Caveats

- **Snapshot.** Each repo is the default-branch HEAD on 2026-10-10.
- **Not a random sample.**
  - Next.js is 33% of the pooled functions, so per-repo values and medians are given.
  - Directory choices shape each repo's numbers.
- **Exclusions are judgement calls.**
  - 28 files with third-party license headers were dropped.
  - zod's locales were kept.
  - Unlabelled generated code could slip through. Header matches were reviewed by hand.
- **Numbers are as the tools report them, quirks included.**
  - sonarjs scores `||`/`??` as 0 and has the nesting leak.
  - Biome has the behaviours in §6.3.
  - The whitepaper would score code heavy in `||`/`??` and callbacks higher than sonarjs does.
- **Biome comparison limits.**
  - 0 and 1 are indistinguishable, and 255 is a cap.
  - 561 VS Code functions were excluded for Biome parse errors.
  - Columns were not verified on lines with non-ASCII text before a function (all diagnostics did map).
- **The attribution sensitivity is a lower bound.**
- **Spearman ρ is inflated by ties** at low scores.
- **Lines** are physical, including comments and blanks.
- **In-file suppressions were deliberately ignored.** A real `ultracite check` would honour them.
- **Environment.** macOS, Node 24.14.1. ESLint warned about Excalidraw's root `.eslintignore`, which flat config ignores; explicit file lists were passed with `ignore: false`.
