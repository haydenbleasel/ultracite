# React effects and their dependency arrays: measurement report

The data behind the post on React effects and the dependency rule, measured on 2026-10-23 and 2026-10-24. Generated tables are in `tables.md`. The machine-readable results are:

- `inventory.json`: the rules per linter and preset, with resolved options, fix kinds, the React Compiler options ESLint's plugin runs with, and Ultracite's own prompt and template lines
- `census.json`: every hook with a dependency array, aggregated per repo and pooled (rows in `out/react-effects/census/`)
- `rule-census.json` and `rule-census.md`: the shared Oxlint census (core + react), all twelve repos and Ultracite
- `corpus-lint.json`: each linter's dependency rule joined hook by hook, raw and reported, the overlap, every disagreement explained, and the messages
- `fixes.json`: what each linter's fix (and ESLint's suggestion) does to every flagged hook, and the signs that the result runs more often, loops, runs less often or throws (rows in `out/react-effects/fixes/`)
- `markers.json`: every directive comment, the dependency rule's suppressions with the hook each covers, the ranking against every other rule, and each repo's own lint config
- `calibration.json`: 53 shapes through every linter and fix pass, 10 runnable behaviour cases rendered with React 19 in every version, and the runtime's validation against react.dev
- `history.json` and `history-labels.json`: hook-rule disable comments over time, bug-search commits linted before and after, and the hand reading of both
- `sample.json`, `suppression-blind.json` and `classifications.json`: the two hand classifications, both raters
- `agent-runs.json`: hooks and effects in the agent experiment's own committed runs
- `decision-history.json`: how Ultracite came to turn these rules on

The agent-experiment subjects are in `corpus/examples/react-effects/`. Everything is regenerated by `research/corpus/scripts/effects-*.cjs` (§9).

Terms used throughout:

- **Hook:** a call to `useEffect`, `useLayoutEffect`, `useInsertionEffect`, `useCallback`, `useMemo` or `useImperativeHandle` (bare or `React.`), or a custom hook whose arguments include a function followed by an array literal. **Effect:** the first three.
- **The dependency rule:** ESLint's `react-hooks/exhaustive-deps`, Oxlint's `react/exhaustive-deps` (it reports as `react-hooks(exhaustive-deps)`, which is also the name Ultracite's agent handoff uses) and Biome's `useExhaustiveDependencies`. **The compiler rules:** the React Compiler checks both Oxlint and ESLint ship, of which `exhaustive-effect-dependencies` and `memo-dependencies` check dependency arrays too.
- **Flagged:** a dependency-rule diagnostic joins to the hook. **Raw and reported:** raw neutralises every disable comment; reported honours them, as `ultracite check` would.
- **`eslint` and `eslint-all`:** Ultracite's ESLint react block applies only to `.jsx` and `.tsx`, so `eslint` is ESLint as configured, and `eslint-all` is the counterfactual with the same block on every `.ts` and `.js` file that has a hook.

## TL;DR

- **Corpus.** The same eight codebases and 694,309 lines as every topic, and the four React codebases from the accessibility post (449,047 lines) as a separate set. React code is in Excalidraw, Next.js's client code, tRPC's React packages, Hono's `hono/jsx` (its own hooks, which follow React's API; the rules apply by name), shadcn/ui, Radix, React Aria and Supabase Studio. Zod, Vite, Astro, VS Code and Ultracite's CLI have none.
  - **2,503 hooks:** 1,059 effects (968 `useEffect`, 86 `useLayoutEffect`, 5 `useInsertionEffect`), 894 `useMemo`, 539 `useCallback`, 8 `useImperativeHandle`, and 3 custom hooks with an array.
  - **Effects per 10,000 lines:** 2.9 in the corpus, 19.0 in the React set. Supabase Studio has 662 of the 1,059.
  - **286 hooks (11%) are in `.ts` or `.js` files**, and 77 of them are effects.

- **What the effects look like** (1,059):
  - **Arrays:** 932 list dependencies (mean 2.5), 110 are empty, 14 have none and 3 aren't array literals.
  - **What they list:** 1,159 values returned by custom hooks (a form, a router, a query's data), 556 props, 233 values derived during render, 175 state values. Only one effect lists an object built during render and none a function built during render; authors already avoid those, or memoise them.
  - **What they do:** 26% return a cleanup. 30% set state, 22% synchronously. 14% touch the DOM, 9% add a listener, 8% set a timer. Only 19 fetch or set state after a promise.
  - **A static reading** in the categories of react.dev's "You Might Not Need an Effect": 38% synchronise with something outside React, 16% derive state, 16% update a form or store through a hook's API, 11% look like event-specific logic, and the rest notify a parent, run once on mount, reset state or chain. It agrees with a hand reading of "needed or not" on 47 of 67 sampled effects (§4.10).

- **What Ultracite turns on.**
  - **ESLint:** every non-deprecated eslint-plugin-react-hooks 7.1.1 rule, as error, in a block scoped to `.jsx` and `.tsx`, plus react-doctor's effect rules.
    - **Two are inert.** With the plugin's defaults, `exhaustive-effect-dependencies` can't report (a feature flag is `'off'`), and `memoized-effect-dependencies` never can.
  - **Oxlint:** `react/exhaustive-deps`, `react/rules-of-hooks`, and all 22 React Compiler rules, from a port in which `exhaustive-effect-dependencies` runs in `all` mode.
  - **Biome:** `useExhaustiveDependencies` and `useHookAtTopLevel`, no options.
  - **Fix kinds.** ESLint's is a suggestion, which `eslint --fix` never applies. Oxlint's missing-dependency fix is dangerous and Biome's is unsafe, so they run only with `ultracite fix --unsafe`. In a default `ultracite fix`, every dependency diagnostic goes to the agent as it is.

- **How often the dependency rule fires** (raw, of 2,503 hooks):

  | | ESLint as configured | ESLint everywhere | Oxlint | Oxlint compiler | Biome |
  | --- | ---: | ---: | ---: | ---: | ---: |
  | corpus (384 hooks) | 8 | 18 | 17 | 28 | 34 |
  | React set (2,119) | 198 | 211 | 212 | 275 | 306 |
  | all | 206 (8.2%) | 229 (9.1%) | 229 (9.1%) | 303 (12.1%) | 340 (13.6%) |

  - **ESLint and Oxlint are the same rule.** They flag the same hooks except 22 in `.ts` files, which ESLint as configured never lints, and one ref read in a cleanup.
  - **Biome flags 137 hooks ESLint doesn't.** 87 have a dependency the effect never reads (often a trigger), 15 the same in a memo, 23 are in `.ts` files, 5 depend on a function that captures nothing reactive (ESLint and Oxlint treat those as stable), 3 use Radix's `useEffectEvent` polyfill (Biome accepts only React's), and 1 is a `useInsertionEffect`, which ESLint doesn't check.
  - **Same hook, different names.** Of 203 hooks ESLint and Biome both flag, 116 ask for different dependencies, because Biome wants the member path the callback reads (`form.reset`, `router.push`).

- **Suppression: the reputation holds where React is the product.**
  - **101 comments disable the dependency rule** (89 in the React set, 12 in the corpus), plus 4 blanket disables over a flagged hook. Supabase Studio has 83, or 12.5 per 100 effects.
  - **The most-suppressed rule** in the React set (89 of 233 directives), in Supabase Studio and in Excalidraw. It's second in Radix, after rules-of-hooks. In the corpus as a whole it's tenth, behind `no-explicit-any` (141).
  - **Rarely explained.** Four give a reason after `--`; 19 have a reason or a comment nearby.
  - **What they're for** (hand classification, all 101): mount-only 43, avoiding a loop 20, a stable value the rule can't see 14, event-like 6, a workaround that's now wrong 6, other 12.
    - Adding the dependencies would change behaviour for 67 (κ 0.71).
    - 43 could use `useEffectEvent` instead, and for 31 adding the dependency is fine. 9 have no better fix.
  - **Biome ignores them.** It still reports 98 of the 101, because they're `eslint-disable` comments.
  - **In Oxlint a suppression costs the whole component.** Its compiler rules skip any component holding a disable comment for `exhaustive-deps` or `rules-of-hooks`, and `react/rule-suppression` reports the comment instead: 158 reports on the corpus. Across the compiler rules, 241 fewer diagnostics are reported than raw (these skips and direct suppressions together). eslint-plugin-react-hooks 7.1.1 doesn't skip.

- **What the suggested fix does** (every flagged hook, suppressed ones included):
  - **ESLint's suggestion rewrites 223 hooks** (178 effects) and adds 449 dependencies.
    - **Every render.** It adds a function built during render to 25 hooks and an object to 6; afterwards, ESLint itself says 33 hooks "change on every render".
    - **Throws.** 7 hooks get a dependency declared after them (the array is read during render: a ReferenceError), and 9 lose a `?.` from a dependency they already list (a TypeError when the object is missing).
    - **Its next suggestion** wraps the function in `useCallback` with no dependency array. That still makes a new function on every render, and in 10 of 13 files it isn't imported.
  - **Oxlint's dangerous fix** rewrites 215 hooks. 7 get a dependency declared after them, and 14 get a path without the `?.` the callback reads it with.
  - **Biome's unsafe fix** rewrites 332 hooks and removes dependencies from 163. 129 of those were reactive, mostly triggers an effect never reads, such as Excalidraw's colour picker focusing its input when the active section changes ([ColorInput.tsx L64](https://github.com/excalidraw/excalidraw/blob/4c00f31ddcc20086bac1020428819fe0b9a30bce/packages/excalidraw/components/ColorPicker/ColorInput.tsx#L64-L68)).
  - **Oxlint's safe fix** (plain `ultracite fix`) changed one hook, which was suppressed.
  - **By hand** (100 hooks, weighted to the 351 flagged; κ 0.84), the suggested fix would be:
    - right for 9.3% of hooks and 0.5% of effects
    - harmless for 31.9%
    - a behaviour change for 38.7%
    - an extra re-run for 11.7%
    - a loop for 8.5%

- **Real bugs are rare; unneeded effects aren't.**
  - **The warning is a visible bug** for 1.5% of flagged hooks (κ 0.62), and latent (it can't be seen today) for 18.7%.
  - **The effect shouldn't exist** for 53% of flagged effects (κ 1.0): mostly resetting state (26%), event-specific logic (13%) or derived state (10%).
  - **Why the code omits the dependency:** a trigger the body doesn't read 25%, an oversight 21%, a stable value the rule can't see 17%, avoiding a loop 15%, mount-only 15%.

- **History** (Excalidraw, Next.js, tRPC, Hono):
  - **Bug fixes.** Of 42 commits whose message points at an effect bug and that changed a hook, 17 fix one: 8 effects that ran twice or too often (mostly Strict Mode in Next.js), 2 stale values, 2 races, 2 ordering bugs, a loop, a missing cleanup and a hydration warning.
  - **The rule named the bug once.** It flagged the buggy hook about the value the bug was about in 1 of the 17 (Hono's `useSyncExternalStore`), and its suggestion would only partly have fixed that one.
  - **Suppressions over time.** Next.js added 86 hook-rule disables and removed 56, after a median of 36 days. 37 of the 63 removals across the repos were rule renames or reconfiguration around React Compiler upgrades; 3 added the dependency.

- **Calibration** (53 shapes, 10 behaviour cases, all run with React 19):
  - **The runtime matches react.dev** on 10 of 10 documented behaviours.
  - **Fixes.** The rule's fix fixes a stale closure (B01), re-subscribes an interval on every tick (B10), reconnects on every keystroke (B02), loops (B03; Biome's `visible.filter` dependency avoids the loop by accident), repeats a mount-only call (B04) and reconnects when the theme changes (B05).
  - **Removals.** Oxlint's removal of an unstable dependency makes the effect stale (B06), and Biome's removal of a trigger stops a refetch (B07).

- **Agents in our earlier experiments never met an effect.** None of the 214 committed runs had a dependency hook before or after. Agents added `useId` in 6 accessibility runs.

- **Agent-experiment subjects** (§10), each flagged by Oxlint's dependency rule, whose diagnostic reaches the agent in Ultracite's default React setup:
  - **A, Hono's `useSyncExternalStore`** before honojs/hono#5166: a real stale subscription. The linters' fix clears every diagnostic and only partly fixes the bug; the project's fix clears them all and fixes it.
  - **B, Supabase Studio's `TimeInput`:** adding the missing `validate` throws on the first render (TDZ). Moving it up first makes typing revert. `useEffectEvent` keeps the behaviour.
  - **C, Excalidraw's `useTTDChatStorage`:** two deliberate omissions, suppressed upstream. Adding the dependencies saves the chat on every prompt keystroke. Oxlint's compiler rule still asks to remove the trigger dependencies after every behaviour-preserving edit.

## 3. Method

### 3.1 The hook inventory (`effects-census.cjs`, `effects-lib.cjs`)

- **Parser.** Each file goes through ESLint's own `Linter` with `@typescript-eslint/parser` and a local rule, which gives the AST and scope analysis exhaustive-deps sees. All 6,542 files parse.
- **Per hook:**
  - the name, whether it's built in (bare or `React.`), and where its name comes from (an import and its source, a local, a global)
  - the owner: the nearest enclosing function named like a component or a hook, and whether the hook sits in an inner function
  - the array's form (none, empty, literal, non-literal) and size
- **Each dependency's kind** comes from where its root identifier was declared, following simple aliases (`const x = props.x`) two levels:
  - prop: a parameter of the owner, or a member of one
  - state, setter or dispatch: from `useState`, `useReducer` or `useActionState`, by array position
  - ref, or `ref.current` when the dependency reads it
  - context, memo or callback: from `useContext`/`use`, `useMemo`, `useCallback`
  - effectEvent, or a transition: from `useEffectEvent` or `useTransition`
  - hookValue: any other hook's result
  - function: an arrow, function expression or declaration in the owner
  - object: an object, array, `new`, JSX, class or regex literal in the owner
  - constant (a `const` primitive literal), derived (any other expression in the owner), let
  - import or outer (declared outside the owner), global (unresolved)

  Each dependency also records whether its declaration comes after the hook (a TDZ when read).
- **Captures:** every value the callback reads from the owner, as the member path it reads (`form.reset`, `user?.id`), whether that path is called, and its kind. This is what each rule compares the array with, and what the disagreement analysis uses.
- **Effect features**, each split into "in the callback itself" and "in a function it creates" (a listener, a timer, a promise callback):
  - the cleanup it returns
  - setState calls, with their arguments (constant, updater, value) and the state they set
  - fetch, promise chains and `await`
  - listeners (`addEventListener`), subscriptions (`subscribe`, `on`, `listen`, …), timers, observers
  - DOM and browser globals, and refs read or written
  - prop calls, calls on other hooks' values, conditions
- **The static reading.** One category per effect, by how strong the sign is:
  - external sync: a listener, subscription, timer, observer, the DOM, storage, a ref write or navigation
  - data fetching: fetch, or a promise whose continuation sets state
  - effect chain: it sets state another effect in the same owner depends on and sets state from
  - reset state on prop change: it sets state to constants and depends on a prop
  - derived state: any other synchronous setState
  - store or form update: `form.reset`, `setValue`, a store's `set*`
  - notify parent: a direct prop call
  - event-specific: a conditional call to something else on reactive dependencies
  - mount-only, or unclassified

  It can't see into the functions it calls: a custom hook's value, an imported helper, a prop callback that is a setter in the parent. §4.10 checks it against the hand reading.

### 3.2 The rules (`effects-inventory.cjs`) and their sources

- **Which rules the presets set** comes from the presets themselves, `oxlint --rules` (category and fix kind), `--print-config` of init's config, `calculateConfigForFile` for `.tsx`, `.jsx`, `.ts`, `.js` and a test file, each react-hooks rule's `meta`, and `biome explain`.
- **The React Compiler options** come from eslint-plugin-react-hooks' own build: `COMPILER_OPTIONS` and its `eprh_*` feature flags.
- **Sources read** with `gh api` at the release tags: Oxlint's `crates/oxc_linter/src/rules/react/exhaustive_deps.rs`, `crates/oxc_linter/src/utils/react_compiler.rs` and the `oxc_react_compiler` crate's suppression and dependency-validation passes at `oxlint_v1.86.0`; Biome's `use_exhaustive_dependencies.rs`, `use_hook_at_top_level.rs` and `react/hooks.rs` at `@biomejs/biome@2.5.15`; and eslint-plugin-react-hooks 7.1.1 as installed.
  - **What they say:** which hooks each rule checks, which values it treats as stable, how it handles member paths, optional chaining, refs, render-built values, async callbacks, unnecessary dependencies and `useEffectEvent`, every message, and what each fix writes. The findings that matter are in §4.1, and the line references in the References.

### 3.3 The linters on the corpus (`effects-linters.cjs`, `effects-disagreements.cjs`)

- **Views and modes.** Every view runs on every file of the twelve repos and Ultracite, raw and reported. Oxlint and Biome lint a mirror for raw; ESLint lints the clone with `noInlineConfig`.
- **Joining diagnostics to hooks.** A diagnostic joins to the innermost hook call whose range contains its position (Oxlint's offset, or ESLint's and Biome's line and column). ESLint's "makes the dependencies … change on every render", which it reports at the declaration, joins through the line it names.
- **Kinds** come from each linter's message: missing, unnecessary, unstable, ref in cleanup, non-literal, complex, async, and so on. The names each diagnostic lists are parsed from the message, or from the compiler's labels. Message examples are picked after sorting, so they don't depend on Oxlint's parallel output.
- **Disagreements.** For every hook one view flags and another doesn't, a reason is assigned by precedence:
  - the file type (ESLint's scope)
  - the hook's name (`useInsertionEffect`) or a custom hook
  - only unnecessary dependencies (in an effect, or in a memo)
  - a member path or method whose root the array already lists
  - an optional chain, an outer value
  - a kind only one view reports
  - what each extra name is in the callback: a stable value, or a function without captured values

### 3.4 Suppressions (`effects-markers.cjs`)

- **Every directive comment** is found among typescript-estree's comments, so strings never count: `eslint-disable[-next-line|-line]`, `oxlint-disable…`, `biome-ignore[-all|-start|-end]` and their `enable` forms.
- **For each comment:**
  - the rules it names and its reason (after `--`, or Biome's `: reason`)
  - a nearby comment: a plain comment on the three lines above, or on the same line
  - its scope (next line, line, block or file)
  - the hook it covers: the innermost hook overlapping the covered line, or every later hook for a block
- **Still needed?** Each covered hook is checked against each linter's raw and reported flags, which says whether the comment silences that linter. Blanket directives (no rule named) that cover a flagged hook are counted separately.
- **The comparison with other rules** has two measures:
  - the number of directives that name each rule, per repo and pooled
  - the shared census's raw-minus-reported per rule, which is what Oxlint's presets see suppressed
- **Policy:** each repo's own lint config lines about hooks, at the pinned commit.

### 3.5 What the fixes do (`effects-fixes.cjs`)

- **Copies.** Every hook-bearing file is copied with its disable comments neutralised, so each fix reaches every hook the rule flags raw. `suppressedUpstream` marks the hooks a maintainer had suppressed.
- **Modes:**
  - **ESLint's suggestions:** the first suggestion of every exhaustive-deps diagnostic (non-overlapping), with the react block on every file. Once, and again repeated until nothing changes (at most three passes).
  - **Oxlint:** `--fix` and `--fix-dangerously`.
  - **Biome:** `check --write` and `--write --unsafe`.

  Each runs with the dependency rule alone.
- **Matching.** Hooks are matched before and after by name and order. An LCS keeps a hook a suggestion created from shifting the others.
- **Per rewritten hook:** dependencies added and removed, with their kinds, and the signs:
  - a function, object or array built in render; a value computed by a call in render
  - a setState in the effect whose state is now a dependency (a feedback loop), conditional or not
  - a prop callback, a prop, a hook's value, context
  - a removed reactive dependency
  - a dependency declared after the hook (a TDZ ReferenceError at render)
  - an added path without the `?.` the callback reads it with
  - a listed optional chain the fix rewrote without its `?.`
- **ESLint's verdict.** Each fixed copy is linted again with ESLint, and its "change on every render" diagnostics are the rule's own judgement of what was added.

### 3.6 Calibration and the runtime (`effects-calibration.cjs`, `effects-runtime.cjs`)

- **Shapes:** `calibration/react-effects/cases.tsx`, 53 cases (C01–C53). They cover missing primitives, props, state, functions (with and without captured values) and objects; setters, `dispatch` and refs; `ref.current` in a cleanup and in the array; `useEffectEvent`, React's and an imported one under another name; a custom hook, with and without each linter's custom-hook option; an async callback; unnecessary dependencies, outer values and imports; optional chaining used and listed; `useCallback`, `useMemo` and `useImperativeHandle`; no array and an empty array; a non-literal array; `useLayoutEffect` and `useInsertionEffect`; a hook in a condition; derived state; a chain; notifying a parent; fetching without cleanup; resetting on a prop; props called through `props`; a hook imported from Preact; member paths and method calls; literals, complex expressions, spreads and duplicates; suppressions placed above the hook and above the array; const literals; assignments lost after render; dependencies declared after the hook; and optional-chain triggers.
- **Configurations:** each case goes through Oxlint (init's config), react-doctor, ESLint (raw and reported) and Biome (the presets), with every message, help, label and suggestion, then through every fix pass.
- **Behaviour:** `behaviour/`, 10 runnable cases (B01–B10), each with a hand-written right fix (`*.right.tsx`).
  - **Versions:** each case runs as written, right, after ESLint's suggestion (once and repeated) and after each Oxlint and Biome fix.
  - **Scenarios:** props changes, clicks, typing, timers and unmount.
  - **Traces:** what the component logged, the text after each step, renders, effect setups and cleanups, warnings, errors and loops. Each version runs in a fresh process.
- **The runtime.** React 19.3.0 and react-dom/client from the Bun store run on a minimal DOM written for this topic: elements, text and comment nodes, attributes, styles, child lists, capture and bubble event dispatch (so React's root listener works), focus, and a window and document.
  - **Instrumentation:** a wrapped JSX runtime counts renders by component; wrapped effect hooks record setups and cleanups by source line, mapped through the transpiler's source map.
  - **Timers and loops:** fake timers are advanced by hand, an async act lets promises settle, and a render cap (500 per act) records a loop instead of hanging.
  - **Validation:** before any case runs, ten validation cases compare it with behaviour react.dev documents.

### 4.9 Calibration

The full matrix is in `tables.md` §6. The cases that matter for the post:

- **The rule catches a stale closure** (B01: an interval pinging the old room). The fix works; it restarts the interval for the new room.
- **The fix is right but costs re-subscriptions** (B10, react.dev's counter): the count reaches 5 with the fix and with the updater-function rewrite, but the fix sets the interval up 6 times instead of once.
- **The fix re-runs the effect too often:**
  - B02: connecting with an object built during render reconnects on every keystroke.
  - B08: a function built during render runs on every render. ESLint's second suggestion, a `useCallback` with no array, changes nothing.
- **The fix loops** (B03: an effect that filters the state it reads, under ESLint and Oxlint). Biome's fix adds `visible.filter` instead, a method that never changes, so its version runs once by accident.
- **The fix changes deliberate behaviour:**
  - B04: a mount-only `onReady` fires after every parent render.
  - B05: a chat reconnects when the theme changes. `useEffectEvent` keeps the original behaviour and satisfies ESLint and Oxlint.
- **The fixes that remove dependencies:**
  - B06: Oxlint's dangerous fix removes a render-built `opts` and leaves `[]`. The effect stops re-running every render, but also stops loading the new id.
  - B07: Biome's unsafe fix removes a `refreshKey` trigger, and the refetch stops.
- **The ref warning is right** (B09): at unmount, `ref.current` is `null` in the cleanup, and the node captured in the effect isn't.
- **Implementation details:**
  - **Constants:** ESLint treats a `const` boolean as reactive and asks for it (C38); Oxlint and Biome don't.
  - **useInsertionEffect:** ESLint doesn't check it (C26); Oxlint's compiler rule and Biome do.
  - **useEffectEvent:** ESLint and Oxlint flag an Effect Event listed as a dependency (C11). They treat any hook named `useEffectEvent` as stable whatever its source, which is why only Biome flags Radix's polyfill; one imported under another name (C30) is flagged by all three.
  - **Unnecessary effect dependencies** are reported only by Biome and Oxlint's compiler rule (C14, C43). Biome's unsafe fix removes the `userId` that resets a comment box (C43).
  - **Outer values:** Oxlint's safe fix removes an outer-scope dependency (C16). One `oxlint --fix` pass removes one of two.
  - **Suppressions:** a suppression above `useEffect(` instead of the array silences neither ESLint nor Oxlint, but still turns off Oxlint's compiler rules for the component (C36). Placed above the array (C51), it silences both, and Oxlint's compiler rules on the component's other effect disappear.
- **The runtime's validation:** 10 of 10. No array re-runs after every render; an empty array runs once; cleanup runs with the old values first; Strict Mode adds a cycle on mount; the stale counter stays at 1; `setState` in a no-array effect hits "Maximum update depth exceeded"; Effect Events read the latest props; layout effects run first; an object dependency re-runs every render; a same-value setState skips the render.

### 4.11 Effects in the agent experiment's own runs

None of the 214 runs (106 Claude Code, 108 Codex, across eight topics) had a dependency hook before or after, and no agent added an effect, a memo or a callback. In 6 of the 50 accessibility runs, agents added `useId` (5 calls in all) to link labels. The earlier subjects had no effects, so these runs say nothing about how agents handle them.

## 5. Findings worth stating carefully

- **The dependency rule is an accurate detector of a narrow fact.** ESLint and Oxlint agree hook for hook: a value the callback reads isn't in the array. Whether that matters is another question, and in the hand sample it rarely did. 1.5% of flagged hooks show a stale value someone can see; for 80% the omission is harmless as written.
- **Its message and its fix assume the opposite.** Every help text says to add the dependency. That's right for 9% of flagged hooks and 0.5% of flagged effects. It changes behaviour for 39%, re-runs or loops for 20%, and in the corpus, throws for 7–9 hooks per linter.
- **Half the flagged effects shouldn't exist.** Both raters agreed on every one (κ 1.0). That's the advice react.dev gives, and none of the dependency rules says it; react-doctor's rules and the compiler's `set-state-in-effect` come closest.
- **Suppressions encode intent, and Ultracite forbids them.**
  - **Mostly deliberate.** Two-thirds of the 101 suppressions guard behaviour that adding the dependency would change, and 43 could be `useEffectEvent`.
  - **Under Oxlint, a suppression costs twice.** It's an error itself (`rule-suppression`), and it turns off the compiler's checks for the whole component.
- **The fixes differ more than the rules.**
  - **ESLint** only suggests, but its suggestions can drop `?.` or reference a declaration below the hook.
  - **Oxlint's dangerous fix** also removes render-built dependencies, which makes the effect stale.
  - **Biome's unsafe fix** removes the triggers that effects use on purpose.
- **History doesn't show the rule preventing bugs.** In 17 effect-bug fixes, it named the bug once. Most were Strict Mode double runs and timing, which no dependency rule sees.

## 6. Caveats

- **Snapshot and mix.** The repos are at their 2026-10 HEADs; the subject A source is from 2026-07, before its fix.
  - **One application.** Supabase Studio, the only application, has two-thirds of the effects and most suppressions, and its effects lean on react-hook-form, React Query, nuqs and valtio.
  - **Libraries.** Radix and React Aria are libraries whose effects are mostly external sync.
- **Static analysis can't see into other files.**
  - **Kinds.** A dependency's kind comes from its declaration in the same file, so props from parents, context values, and custom hooks' return values (1,159 dependencies) are labelled by where they come from, not by whether they're stable.
  - **Signs.** The "every render" and loop signs are lower bounds for the same reason, and the hand reading decides them case by case.
- **The categories are a static reading.** It agrees with the hand reading on needed-or-not for 70% of sampled effects, and misses side effects behind hook APIs.
- **Raters are Claude models.**
  - **Agreement:** κ is 0.62–1.0 on hooks and 0.47–0.78 on suppressions; `justified` (0.47) and the suppression fix (0.51) agree least.
  - **One rater** read the history and the decision history.
  - **Assumed stability:** rater 1 assumed the identity of a few third-party values (react-hook-form, nuqs, React Query, React Aria's `useEffectEvent`), and said so in notes.
- **The fix analysis applies fixes to suppressed hooks too** (97 of 223 for ESLint). §4.7 gives the counts without them.
- **History is thin and mainline-only.** See §4.8.
- **The runtime is a minimal DOM.** It's validated on ten documented behaviours and enough for the cases and subjects; it doesn't do layout, CSS or real browser events beyond dispatch and focus.
- **The agent runs are from other topics**, whose subjects had no effects.

## 7. Notes on Ultracite itself

These are raised for Hayden, not fixed.

1. **ESLint's react block skips `.ts` files.** `config/eslint/react/eslint.config.mjs` sets `files: ["**/*.jsx", "**/*.tsx"]`, so every react-hooks rule (and react-doctor) is off for custom hooks written in `.ts`.
   - **In the corpus:** 286 hooks, 11% of them, including Excalidraw's `useTTDChatStorage.ts` (subject C) and Hono's hooks (subject A).
   - **The other linters:** Oxlint and Biome check those files, so the three presets diverge on 22–23 flagged hooks.
2. **Two ESLint compiler rules are on and can't fire.** `react-hooks/exhaustive-effect-dependencies` is gated by a feature flag that's `'off'` in 7.1.1, and `react-hooks/memoized-effect-dependencies` has no diagnostics at all. Oxlint's `react/exhaustive-effect-dependencies`, which the parity script treats as the same rule, runs in `all` mode and reports on 303 hooks.
3. **Oxlint and ESLint handle suppressions differently.** Oxlint's compiler rules skip any component with a disable comment for `exhaustive-deps` or `rules-of-hooks` and report `react/rule-suppression` (158 reports on the corpus). ESLint's don't skip and report nothing.
4. **The Biome preset's dependency rule isn't the ESLint and Oxlint rule.**
   - **It reports more.** Unnecessary dependencies in effects (87 of the 137 hooks only Biome flags), and functions without captured values.
   - **It's narrower about hooks.** It treats `useEffectEvent` as stable only from React, and checks built-ins only when imported from React, so it skips Hono's hooks entirely.
   - **Its unsafe fix removes trigger dependencies** (129 reactive removals; Excalidraw's colour-picker focus).
5. **Oxlint's fixes can change behaviour.**
   - **Plain `ultracite fix`:** the safe fix removes outer-scope and `ref.current` dependencies (C16, C46; one corpus hook, suppressed).
   - **`--unsafe`:** the dangerous fix removes a dependency that changes every render, leaving a stale effect (B06), and prints paths without `?.` (14 corpus hooks).
6. **Agent guidance.**
   - **The template.** It says "Specify all dependencies in hook dependency arrays correctly" (`src/data/rules.ts`, the skill's `code-standards.md`). In the hand sample, adding the dependency is the best fix for 30% of flagged hooks and 21% of flagged effects. The template doesn't mention `useEffectEvent`, updater functions, or that an effect may not be needed.
   - **The prompt.** "preserve runtime behavior" conflicts with fixing a real stale-value bug (subject A), and its ban on suppressions leaves `useEffectEvent` or "Left for review" for deliberate omissions (subject C).
7. **react-doctor's effect rules differ between presets.** Nine are on in ESLint's react preset and not in Oxlint's js-plugins preset (`inventory.json` `reactDoctorDifferences`). The parity script doesn't check react-doctor.
8. **Decision history** (`decision-history.json`):
   - **When they came on:** Biome's two rules came with the react preset (#319, 2025-10); ESLint's every-rule loop with V7 (#466, 2025-12); Oxlint's 22 compiler rules with the 1.79 update (972b9468, #775, 2026-08), "matching the ESLint react preset".
   - **No discussion:** no issue or PR discusses the dependency rule's merits, `useEffectEvent`, or suppressions.
9. **Upstream bugs to report:**
   - **ESLint (eslint-plugin-react-hooks 7.1.1)**
     - The exhaustive-deps suggestion drops `?.` from listed dependencies the callback doesn't read (C52; it throws).
     - The "wrap in useCallback" suggestion writes no dependency array and doesn't add the import (B08; 13 corpus hooks, 10 without the import).
   - **All three:** the fix adds a dependency declared below the hook, which throws a ReferenceError at render (C53, subject B; 7–9 corpus hooks). A message noting the declaration order would help.
   - **Oxlint 1.86.0:** the dangerous fix for "changes every render" removes the dependency (B06).
   - **Biome 2.5.15:** only React's `useEffectEvent` is stable, so same-named polyfills are flagged (3 corpus hooks).
