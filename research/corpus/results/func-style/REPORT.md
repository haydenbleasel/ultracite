# func-style and no-use-before-define: measurement report

The data behind the post on how functions are written and ordered, measured on 2026-10-29 and 2026-10-30 (one full run of `func-style-run-all.cjs`). Generated tables are in `tables.md`. The machine-readable results are:

- `rules.json`: what Ultracite's presets set for every function-style and order rule, per linter and preset (ESLint resolved per file type, including a TanStack route file), fix kinds, Biome's rules with `biome explain`, the agent prompt's and AGENTS.md template's lines, and the preset inconsistencies
- `census.json`: the inventory (every function's form, scope, body, types and what converting it would need), file order, mutual recursion, and every use-before-define candidate with its runtime class, per repo and pooled, source and tests apart (rows in `out/func-style/census/`)
- `linters.json`: each rule alone in Oxlint, ESLint and Biome with its option variants, raw and reported, every disagreement with a reason, and every message
- `rule-census.json`, `rule-census.md`: the shared Oxlint census with Ultracite's core, react and js-plugins presets
- `calibration.json`: 44 hand-written cases through every linter configuration, `tsc` and Node, as written and converted, and every fix pass
- `convert.json`: every reported declaration converted on copies, the references and crashes that creates, the reordering that would satisfy both rules, and the type checks
- `cycles.json`: runtime import cycles that are safe only because of a hoisted declaration
- `history.json`, `history-labels.json`: keyword commits and their hand reading, style churn, bug fixes by function form
- `markers.json`: the projects' own lint settings and disable comments for these rules
- `sample.json`, `classifications.json`: the hand classification, both raters
- `agent-runs.json`: function style in the agent experiment's committed runs

The agent-experiment subjects are in `corpus/examples/func-style/`. Everything is regenerated by `research/corpus/scripts/func-style-*.cjs` (§9).

Terms:

- **Declaration:** `function f() {}`, including `export function` and `export default function`.
- **Variable-bound function:** a `const`, `let` or `var` whose initialiser is an arrow or a function expression (through `as`, `satisfies` or `!`). A **const function** is the `const` kind.
- **Reported declaration:** one ESLint's `func-style` with Ultracite's options reports: every declaration except `export default function` and TypeScript overloads.
- **Use-before-define candidate:** a value or type reference above its binding's first definition, or read during its own initialisation (what `no-use-before-define` checks). Its **runtime class** says what happens when the code runs (§3.3).
- **Top-down / bottom-up:** for references between module-level functions, whether the callee is defined below the caller (top-down, the stepdown order) or above it.
- **Corpus, React set, external:** the eight repos of every topic; the four React codebases from the accessibility post; both. Ultracite's CLI is listed apart and never pooled.

## TL;DR

- **Corpus:**
  - **Source:** 52,834 functions in 6,488 files (1,143,356 lines), the same functions as the length-limits topic.
  - **Tests:** 52,218 functions in 2,144 files.
  - **Ultracite's CLI:** 902 functions, no declarations.
- **How named functions are written** (external source): 10,418 declarations and 8,657 variable-bound functions (8,631 `const`, 8,582 of them arrows). Declarations are 54.6% of named functions.
  - **Corpus repos:** 69.1% declarations (Next.js 86.9%, VS Code 92.7%).
  - **React set:** 31.5% declarations (Supabase 24%). In the corpus, Excalidraw uses declarations for only 6.3%.
- **What func-style reports:** 10,134 declarations with Ultracite's options (88.6 per 10,000 lines), from 9.1 (Excalidraw) to 223 (shadcn/ui).
  - **Rank:** second in Ultracite's Oxlint presets on this corpus, after `sort-keys`.
  - **no-use-before-define:** fourth, with 5,428 reports (47.5 per 10,000), from 6.5 (shadcn/ui) to 159 (Radix).
  - **Fixes:** neither rule has an autofix in any linter.
- **Same rule, three implementations:**
  - **func-style:** ESLint and Biome's nursery `useConsistentFunctionStyle` agree on all 10,134. Oxlint reports 10,127; it skips declarations that share a name with a type alias, interface or namespace.
  - **no-use-before-define:** Oxlint and Ultracite's ESLint rule agree on all but one report (ESLint also flags an erased computed key in a type literal).
  - **Biome's `noInvalidUseBeforeDeclaration`** reports nothing in the whole corpus.
- **Hayden's reasons, measured** (external source):
  - **Dropping braces:** 29.3% of declarations (3,051) are a single `return`. Of today's variable-bound arrows, 15.3% are concise and 9.9% more are blocks with a single return.
  - **Assigning types earlier:** 8.1% of const functions (699) are typed through the variable, mostly named types (`NextPageWithLayout`, `SubmitHandler`, `React.FC`). 60.5% of declarations write out every parameter type and the return type; 20.4% of const functions do.
  - **Hoisting compensating for order:** 19.9% of declarations (2,078) are referenced above their line. But 70% of the 11,041 references between module-level functions point up: 770 files are bottom-up and 250 top-down. Files of declarations point down 33.8% of the time, files of const functions 22.2%.
- **What hoisting is used for:** all 3,344 non-type candidates that point at a declaration are harmless today. 3,284 sit inside functions that run later; 60 run on the spot (19 at module load, 41 in a function body).
  - **No crash in shipping code:** no candidate is a read before initialisation.
  - **Hand sample:** 80 of 80 reports harmless; κ 1.0 between raters.
- **Converting every reported declaration** (on copies, 2,828 files):
  - **Forms:** 10,094 become arrows; 40 need a function expression (18 use `this` or `arguments`, 22 are generators); 284 aren't reported.
  - **Crashes:** 19 references in 14 files throw at import (Next.js's `new IntersectionObserver(handleIntersect, …)`), and 41 in 25 files throw when their function runs.
  - **Type errors:** TypeScript adds 340 errors in the eight corpus repos: assertion functions lose narrowing (TS2775 ×82), `never` functions too, plus the TDZ reads.
  - **Reordering:**
    - **Lists affected:** 839 statement lists in 787 files have a reference above its binding after conversion.
    - **Fixable:** 720 lists have a valid order; reaching it moves 2,234 statements (47,828 lines).
    - **No valid order:** 119 lists in 111 files (47 mutual recursion, 72 depending on code that can't move).
    - **Result:** Oxlint's `no-use-before-define` drops from 4,500 to 564 in the converted files.
  - **Already reported before:** with `functions: true`, all 3,328 references to converted functions were reported before the conversion.
- **Module cycles:** 2 of 31 runtime import cycles are safe only because a hoisted declaration is called at load (Next.js). As consts they become load-order hazards.
- **History** (eight repos, three years, 12,762 mainline commits):
  - **Bugs:** of 182 keyword commits, none is a hoisting bug. 3 are TDZ crashes from evaluation order. zod reverted a change that, in its message's words, "traded a hoisted function re-export for a TDZ-bound const and fixed nothing".
  - **Churn:** form changes are rare (36 commits to declarations, 11 to expressions).
  - **Bug fixes, size controlled:** declarations' odds ratio is 0.75 [0.60, 0.92], 0.81 [0.63, 1.03] with scope, 0.87 [0.71, 1.08] with churn. Declarations used above their line: 0.97 [0.83, 1.14]. No robust difference.
- **Policy:**
  - **func-style:** no repo configures it.
  - **Radix** reports only same-scope reads and is the most top-down codebase (64.2% of references point down).
  - **Next.js** enabled typescript-eslint's rule in 2022 and turned it off in 2023.
  - **Disable comments:** none names these rules.
- **Hand classification** (82 declarations, 80 reports):
  - **Conversion:** 84.6% clean, 15.4% need reordering (κ 1.0).
  - **Readability:** the converted code reads the same in 95.4%, worse in 4.6% (κ 0.67).
  - **Concise body:** possible for 33.7% (κ 0.93).
- **Agents** (240 committed runs):
  - **Placement:** every helper with a caller went above it (98 of 98), so no run added a `no-use-before-define` report.
  - **Retries:** `func-style` was in 19 of 37 retries (65 issues), all in length-limits.
- **Notes for Hayden** (§7):
  - Biome users get no func-style.
  - Oxlint's func-style skips declarations that share a name with a type, interface or namespace.
  - `react/function-component-definition`'s fix turns a component read at load time into a const that throws at import (TanStack routes, route tables).
  - Oxlint's version of that rule and `prefer-arrow-callback` undo each other on `memo` and `forwardRef` components.
- **Subjects** (§10): A, Next.js `duration-to-string.ts` (converts cleanly); B, Supabase `ConfigurationDriftPage.utils.ts` (written top-down, needs reordering); C, Astro `serialize.ts` (mutual recursion, no valid order).

## 3. Method

### 3.1 The inventory (`func-style-census.cjs`, `func-style-lib.cjs`)

One ESLint `Linter` pass per file, with the TypeScript parser and its scope manager, walks the whole tree.

- **Every function:**
  - **Form:** declaration, export, export default; `const`/`let`/`var` arrow, or named or anonymous function expression; method, class field, object property, callback, IIFE, other.
  - **Scope:** module, namespace, module block, nested, nested block.
  - **Component:** whether it's a React component (a PascalCase name and JSX in its own body, in a `.tsx` or `.jsx` file).
  - **Body:** concise, block, or a single `return`.
  - **What it reads through arrows:** `this`, `super`, `new.target`, `arguments`.
  - **Types:** parameters, return type, predicates and assertions, `never`, generics, a variable annotation, `satisfies` or `as`.
- **For declarations:**
  - **Signatures:** overloads, as ESLint checks them and also any same-named signature.
  - **Name sharing:** a namespace merge, or a same-named type or interface.
  - **Use:** reassignment, being constructed with `new`, `instanceof`, `.prototype`, `.call`/`.apply`/`.bind`, and references above their line.
  - **Across files:** importers that construct an exported declaration, found by resolving relative imports and by name.
- **File order:** each reference between two module-level function bindings counts as up or down. A file with two or more such references is top-down when at least 75% point down, bottom-up when at least 75% point up, otherwise mixed. Tarjan's algorithm finds mutual recursion.
- **Use-before-define candidates:** as ESLint's rule defines them. Anything under a type annotation, type literal or type query counts as type-only.
- **Check:**
  - **func-style:** ESLint reports exactly the predicted declarations in every repo.
  - **TS files:** typescript-eslint's `no-use-before-define` reports exactly the non-type candidates.

### 3.2 The linters (`func-style-linters.cjs`)

- **func-style:** Ultracite's options; `"declaration"`, with and without arrows.
- **no-use-before-define:** defaults (Ultracite's setting in every linter); `"nofunc"`; and with everything but same-scope reads turned off.
- **Related rules:** `func-names`, `prefer-arrow-callback`, `arrow-body-style`, `unicorn/consistent-function-scoping`.
- **Biome:** `useConsistentFunctionStyle` (nursery, both styles), `noInvalidUseBeforeDeclaration`, `useArrowFunction`, `useConsistentArrowReturn`, `useNamedFunction`.
- **Joins:** every diagnostic is joined to its declaration, declarator or candidate. Every item two implementations treat differently gets a reason from the inventory.

### 3.3 Runtime classes

- **hoisted-function:** the binding is a declaration. *Same-context* if the reference runs on the spot (at module load, or earlier in the same function body), *deferred* otherwise. Harmless today; after conversion the same-context ones throw.
- **deferred:** a `const`, `let` or class read inside a function, method or field initialiser that runs later.
- **deferred-maybe-module-evaluation:** inside a callback passed to a call at load time, where the callee isn't known to call it synchronously (`forwardRef`, `memo`, `createHMRHandler`), or inside a function passed somewhere at load time.
- **tdz-module-evaluation, tdz-same-scope, tdz-indirect, tdz-callback:** read before initialisation, so a crash. In order: in the module's own code; in the same function body; inside a module-level function called at load time before the binding's line (counting only calls in that function's own context); or inside a callback of a synchronous call at load time (`Array#map`, `new Promise`).
- **type-only, export-specifier:** no runtime read, or an export list.
- **Checked by hand:** a looser first version called 23 candidates crashes. Each was read, and all are deferred. The refined analysis calls none of them crashes.

### 3.4 Conversion and reordering (`func-style-convert.cjs`)

- **Conversion:** each reported declaration becomes either `const f = (…) => {…};` or `const f = function f(…) {…};`.
  - **Arrow:** keeps `export`, `async`, type parameters (with `<T,>` in `.tsx`) and the return type.
  - **Function expression:** used when the function reads `this`, `arguments` or `new.target`, has a `this` parameter, is constructed, uses `.prototype` or `instanceof`, or is a generator.
  - **Left as they are:** overloads, default exports and namespace merges.
  - **Scope:** source files only.
- **Checks on the copies:**
  - **Parsing:** every file is parsed again with typescript-estree and TypeScript.
  - **References:** every reference to a converted binding is classified.
  - **Lint:** Oxlint's two rules run on the original, converted and reordered copies.
- **Reordering:** within every statement list, statements move so each binding is defined above its value references.
  - **What may move:** only statements with no effects: function bindings, pure declarations, side-effect-free classes and enums, and export lists. Overload groups move together.
  - **Algorithm:** Kahn's algorithm, taking the smallest original index first. Moved statements are those outside the heaviest increasing subsequence, weighted by lines.
  - **No valid order:** the deferred references inside the cycle are dropped (they stay reported), and the best order is still applied.
- **Type checks:** each corpus repo's own tsconfig, with the copies overlaid; added diagnostics are counted by file and code. Only zod and hono resolve every import. The React set wasn't type-checked.

### 3.5–3.11

- **Module cycles** (`func-style-cycles.cjs`): uses `import-cycles-graph.cjs` `analyse`, unchanged. A late-use cycle with a top-level read of a function declaration "flips" once declarations are converted. Its runtime cycle counts equal `results/import-cycles/graph.json` in all eight repos.
- **History** (`func-style-history.cjs`):
  - **Keywords:** the whole mainline history of each clone, searched for TDZ, hoisting, "before initiali[sz]ation", "Cannot access", "is not defined", `ReferenceError`, cycles and the rule names. Every commit was read (`history-labels.json`, one rater).
  - **Churn:** form changes and moved definitions, by a line heuristic. The two largest conversion commits were read: both are refactors.
  - **Bug fixes:** `length-history.cjs`'s `track`, unchanged, followed by logistic regressions on form, log own lines, log exposure and repo effects, with errors clustered by file. The bug-fix heuristic is 73.7% precise and misses 15.5% of other commits (the length topic's hand check).
- **Policy** (`func-style-markers.cjs`): lint configs at each pinned commit, with the commit that added each setting, and disable comments.
- **Hand classification** (`func-style-sample.cjs`, seed 20261029):
  - **Declarations:** 6 per repo at random, plus 10 oversampled (function expressions, assertion or never-returning, used at load).
  - **Reports:** 80 of Oxlint's reports, stratified by class.
  - **Raters:** rater 1 saw the automatic labels; rater 2, blind, labelled 30 of each.
  - **Shares:** weighted by population.
- **Calibration:** 44 cases. **Agent runs:** the subject as handed over against the final file, plus every retry prompt. **Subjects:** §10.

### 4.1 What Ultracite turns on

- **Fixes:**
  - **No fix:** func-style (Oxlint "pending") and no-use-before-define have none in any linter.

- **Messages:**
  - **func-style:** ``Expected a function expression.`` Oxlint's help is ``Enforce the consistent use of either `function` declarations or expressions assigned to variables``. Biome's nursery rule says `Function expressions are required here, but this is a declaration.`

- **What agents are told:** the agent prompt asks for "the minimal change that resolves each issue while preserving runtime behavior", forbids suppressions and allows `Left for review:`. The AGENTS.md template says "Use arrow functions for callbacks and short functions" and nothing about order.

### 4.8 What converting costs

- **Decisions:** 10,094 arrows; 40 function expressions; 284 not reported (216 default exports, 68 overloads).
- **References to converted bindings:** 3,328, all already reported.

- **Lint and parsing:**

  - **no-use-before-define:** 4,500 before and after conversion, 564 after reordering.
  - **Parsing:** every converted and reordered file parses.

## 5. Findings worth stating carefully

- **The presets already require bottom-up order.** No linter fixes func-style, and `no-use-before-define` at its defaults already reports 3,344 hoisted uses. Converting changes which reports would crash, not how many there are.
- **Hayden's reasons hold in part.** A third of declarations could drop their braces. Few const functions take their type from the variable. Even files of declarations are mostly written bottom-up.
- **Hoisting isn't where the bugs are.** No shipping code reads before initialisation, and the history finds no hoisting bug. Hoisting matters at load-time references (19) and in module cycles (2), which is exactly where converting creates the hazard.
- **Conversion is mostly mechanical, with sharp edges.** The hazards are load-time reads, nested declarations used above their line, assertion and `never` functions, and mutual recursion.
- **Agents already put helpers above callers.** func-style is the rule they trip when they write declarations in a declaration-style file.

## 6. Caveats

- **Snapshot and mix:** HEADs from 2026-10. Next.js and Supabase dominate their sets.
- **Measured without the rules:** only Radix (same-scope order) and Next.js's examples enforce any order.
- **Static analysis:** member calls at load and unusual synchronous callees are missed, and the "maybe" class over-counts. The 23 earlier crash candidates were read by hand.
- **The reorderer** finds one valid order, not necessarily the one a person would pick. It split one overload group in Next.js.
- **Type checks:** unresolved imports are `any` outside zod and hono, so lost narrowing is under-counted. The React set wasn't type-checked.
- **History:** one rater for the keywords; the churn count is a heuristic; the bug-fix heuristic is 73.7% precise. These are associations, not effects.
- **Raters are Claude models.** Rater 1 saw the automatic labels. Rater 2 ran a one-line `node -e` to check its labels file parsed, which its brief didn't allow.
- **The agent runs** came from other topics. Length-limits' handoff filter shaped its retries.

## 7. Notes on Ultracite (for Hayden, not fixed)

1. **Biome users get no func-style.** `nursery/useConsistentFunctionStyle` (since 2.5.14) matches ESLint on all 10,134 declarations, but nursery rules are off (#457).
2. **Oxlint's func-style skips declarations that share a name** with a type alias, interface or namespace (c32, c33).
3. **`react/function-component-definition`'s fix can break files.** ESLint's autofix (`ultracite fix`) and Oxlint's suggestion (`--unsafe`) turn a component that's read at load time into a const that throws at import (c23, c44). The tanstack preset turns `no-use-before-define` off in route files, so nothing reports it afterwards.
4. **Oxlint's `react/function-component-definition` and `prefer-arrow-callback` undo each other** on unnamed `memo` and `forwardRef` components: `unnamedComponents` defaults to `"function-expression"`.
5. **`no-use-before-define` at its defaults reports 5,428 lines and no crash.** Radix's setting reports 36. The TanStack comment's claim that tsc catches real TDZ crashes holds for direct reads, but not for callbacks or calls at load time (c28, c29).
6. **Converting isn't a safe mechanical fix.** Assertion and `never` functions need an explicit function type, and load-time references need a move.
