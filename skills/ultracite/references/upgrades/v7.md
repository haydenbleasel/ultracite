# Upgrading to Ultracite v7

Ultracite v7 supports three linters (Oxlint + Oxfmt, Biome, and ESLint + Prettier + Stylelint), so every preset path names its linter. It also removed the `lint` and `format` commands, which v5.3 had already renamed to `check` and `fix`. Projects set up on v6 or earlier use Biome.

## Does the project need it?

Yes, if either of these is true:

- A Biome config (`biome.json` or `biome.jsonc`, including nested ones in monorepo packages) extends an Ultracite preset without a linter segment, such as `ultracite/core` or `ultracite/react` instead of `ultracite/biome/core`.
- Something still runs `ultracite lint` or `ultracite format`: a `package.json` script, a Husky hook in `.husky/`, a lint-staged config (in `package.json`, `.lintstagedrc*` or `lint-staged.config.*`), `lefthook.yml`, `.pre-commit-config.yaml`, or a CI workflow in `.github/workflows/`.

## Steps

1. In every Biome config, rename each `ultracite/<preset>` entry in `extends` to `ultracite/biome/<preset>`. The v6 presets are `core`, `react`, `next`, `solid`, `vue`, `svelte`, `qwik`, `angular`, `remix` and `astro`. Keep the order of `extends` and every other setting in the file.

   ```jsonc title="biome.jsonc"
   {
     // v6: "extends": ["ultracite/core", "ultracite/react", "ultracite/next"]
     "extends": [
       "ultracite/biome/core",
       "ultracite/biome/react",
       "ultracite/biome/next",
     ],
   }
   ```

2. Replace `ultracite lint` with `ultracite check`, and `ultracite format` with `ultracite fix`, everywhere they run. Keep their arguments, including file paths and `--unsafe`.

3. Keep the project on Biome. v7 can move a project to Oxlint or ESLint, but that's the user's choice to make with `npx ultracite init --linter oxlint` (or `eslint`), not part of the upgrade.

## Check

`npx ultracite doctor` passes, and `npx ultracite check` runs without a configuration error.
