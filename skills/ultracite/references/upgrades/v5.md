# Upgrading to Ultracite v5

Ultracite v5 moved to Biome 2, whose configuration format differs from Biome 1's. Every later release uses Biome 2 too.

## Does the project need it?

Yes, if the Biome config (`biome.json` or `biome.jsonc`) still uses Biome 1's format: its `$schema` points at a 1.x schema (such as `https://biomejs.dev/schemas/1.9.4/schema.json`), or it has a top-level `organizeImports`, `files.ignore` or `files.include`.

## Steps

1. Set `$schema` to `./node_modules/@biomejs/biome/configuration_schema.json`. Leave `"extends": ["ultracite"]` as it is; the v6 and v7 guides rename it.

2. Move Biome 1 settings to their Biome 2 form:

   - `files.ignore` and `files.include` become a single `files.includes` list. Start it with `"**"`, then add each ignored path with a leading `!`. Globs no longer get an implicit `**/` prefix, so an ignored `dist` becomes `"!**/dist"`.
   - `organizeImports` moves to `assist.actions.source.organizeImports`, set to `"on"` or `"off"`.
   - `linter.rules.all` is gone, with no replacement. Remove it.
   - Paths and globs are now relative to the config file, not the folder Biome runs in.

   If you can run commands, `npx @biomejs/biome migrate --write` makes most of these changes. Review what it writes.

3. Biome 2 reads suppression comments as `// biome-ignore lint/<group>/<rule>: <reason>`. Rewrite any in the old `lint(<group>/<rule>)` form.

4. `biome.json` keeps working. v5 wrote `biome.jsonc` for new projects, but there's no need to rename an existing file.

## Check

`npx ultracite check` runs without a configuration error.
