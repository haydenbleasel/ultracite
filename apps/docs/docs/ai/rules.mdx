Ultracite provides seamless integration with AI coding assistants by automatically generating agent rule files. These rules help guide AI assistants to write better, more consistent code that follows best practices.

The agent rules work alongside your linter's formatting and linting. While your linter handles code formatting and catches errors, the agent rules guide AI assistants to write better code from the start, reducing the need for fixes later.

The generated rules intentionally focus on code quality and implementation guidance instead of hardcoding formatter-specific settings like line width, quote style, or trailing commas. That keeps the rules portable across repositories while still letting each project's configured formatter stay in charge.

This dual approach ensures both automated code quality (through linting) and intelligent code generation (through AI coding rules).

## Setup

### Automatic Setup

When you run `npx ultracite init`, you'll be prompted to select which agent files you want to add:

```text
? Which agent files do you want to add (optional)?
  ◯ Universal (creates AGENTS.md for Codex, Jules, Devin, and more)
  ◯ Claude (creates .claude/CLAUDE.md)
  ◯ Replit (creates replit.md)
  # ... and more
```

This will create the relevant rule file(s) in your project directory.

Files that other tools also write to, like `AGENTS.md` and `.claude/CLAUDE.md`, get an Ultracite block (starting at `# Ultracite Code Standards`) added below your own content. Re-running `init` replaces that block in place, removes any duplicate blocks earlier versions appended, and keeps the file's line endings. The rules tell agents to run your project's installed CLI, such as `npx ultracite fix` or `pnpm exec ultracite fix`.

Firebender's rules go in `.firebender/rules/ultracite.mdc` with `alwaysApply: true`. Earlier versions wrote them into `firebender.json` by mistake; if that file still holds only those rules, `init` resets it to `{}`.

### Manual Setup

If you want to manually set things up, create the rule file for your agent (see [Supported Agents](#supported-agents) below) in your project directory. Then, copy and paste [this content](https://github.com/haydenbleasel/ultracite/blob/main/packages/cli/src/data/rules.ts) into the file.

### Aider

Aider doesn't load an instructions file on its own, only the files `.aider.conf.yml` lists under `read`. So for Aider, `init` writes the rules to `AGENTS.md` and merges two keys into `.aider.conf.yml`, leaving the rest of the file as it was:

```yaml title=".aider.conf.yml"
read: AGENTS.md
lint-cmd: npx ultracite fix
```

Aider lints every file it edits, so `lint-cmd` makes it run `ultracite fix` on each one. When problems are left, Aider shows them to the model and asks it to fix them before moving on. If your config already sets `lint-cmd` to another linter, `init` leaves it alone: a `lint-cmd` without a language replaces Aider's per-language linters. Earlier versions wrote the rules to `ultracite.md`, which Aider never loaded; `init` removes it if it holds nothing but the rules.

## Reusable Skills

If your AI tool supports installable reusable skills, see the [Agent Skills](/docs/ai/skills) guide. The global Ultracite skill gives you the same baseline guidance across repositories while leaving formatting decisions to each repo's configured linter and formatter.

## Benefits

Using Ultracite agent rules provides several advantages:

- **Consistency**: All AI-generated code follows the same conventions
- **Quality**: Rules enforce best practices and prevent common mistakes
- **Accessibility**: Built-in accessibility guidelines ensure inclusive code
- **Performance**: Rules promote efficient patterns and avoid anti-patterns
- **Security**: Guidelines help prevent common security vulnerabilities

## Customization

While the default rules are comprehensive, you can customize them for your specific needs:

1. **Modify existing rules**: Edit the rule files directly, but keep your changes outside the Ultracite block in shared files like `AGENTS.md`, since re-running `init` replaces it
2. **Add project-specific rules**: Append additional guidelines
3. **Disable rules**: Remove or comment out rules that don't apply to your project
